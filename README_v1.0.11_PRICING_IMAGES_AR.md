# Maria CFO Web v1.0.11 — تصحيح تسعير المواد وواجهة الصور

## مصدر الإصدار

هذا إصدار كامل مشتق من ZIP المعتمد `Maria-CFO-Web-v1.0.10-FULL-NO-CONFIG.zip`، وليس من المشروع القديم v1.0.2. يتضمن ملفات الموقع وقاعدة البيانات والتوثيق والاختبارات. **ملف config.js غير موجود** ويجب الحفاظ على الملف الموجود في الاستضافة.

## 1. اعتماد التسعير بالدولار

- أعيدت كتابة دالتي `material_price_initialize_usd_v110` و`material_price_set_exchange_rate_v110` باستخدام تحديث جماعي بدلاً من مئات تحديثات الحلقة الفردية، مع حفظ سجل تغييرات الأسعار. التحسين قد يحل مهلة التنفيذ الناتجة عن العملية السابقة، لكنه **لم يُختبر على قاعدة Supabase الحية**؛ لذلك تعرض الواجهة الآن رمز/سبب الخطأ من قاعدة البيانات بدل الرسالة العامة.
- تسعير المادة ذات آخر تكلفة معتمدة **صفر** أو غير المعروفة يبقى NULL بالدولار ولا يؤثر فيها تغيير سعر الصرف. لا ينشأ سعر بالدولار من الصفر.
- في نموذج المادة، إدخال صفر أو ترك سعر الدولار فارغًا يعني **سعر دولار غير محدد**، بينما القيم السالبة تُرفض.
- التسعير المرجعي لا يغيّر آخر سعر شراء تاريخي، أو فواتير الشراء، أو حركات المخزون، أو قيود الصناديق.
- تغيير سعر الدولار من الإعدادات: قرار **تحديث أسعار المواد المرجعية** أو **عدم التحديث**؛ الخيار الثاني يغيّر سعر الصرف فقط. كلاهما ضمن عملية قاعدة بيانات واحدة.
- إذا فشل الاعتماد، راجع الرسالة المحدثة التي تتضمن رمز الخطأ (مثل PGRST202 أو 57014 أو 42501). **لا تفترض نجاح العملية لمجرد إغلاق النافذة**.

## 2. شاشة صور فواتير الشراء

- الصورة على يمين الشاشة. على يسارها ترويسة الفاتورة، ثم قائمة البنود ذات تمرير عمودي مستقل.
- كل بند بطاقة بعناصر كاملة العرض: اسم المادة، مطابقة المادة، الوحدة، الكمية، السعر، الإجمالي، الخصم والحذف. لا يوجد تمرير أفقي للبنود على الكمبيوتر أو الهاتف.
- لا يوجد مربع «راجعت الصورة/الأرقام» داخل البنود أو نافذة المراجعة. يبقى التحذير عند اختلاف الأرقام، ويظل الضغط على **حفظ ونشر الفاتورة** في المراجعة النهائية قرار النشر.
- أُزيلت الشروح الطويلة للكمية المحسوبة ووحدات العبوات، وبقيت كلمة «مقترحة» صغيرة بجانب الكمية المستنتجة. لم تُغيّر طريقة OCR نفسها، ولم تُلغَ حماية مطابقة المادة ووحدة الشراء وقيم الكمية/السعر الصحيحة.
- الصورة المخزنة محليًا والبنود المحررة لا تُحذف بهذا التحديث. لم يتغير مسار حفظ فواتير الشراء المالي.

## 3. ملف دفتر اليومية المرفق

**لم نستورد دفتر اليومية إلى قاعدة البيانات.** التحليل الوصفي موجود في `docs/ANALYSIS_DAILY_LEDGER_v111_AR.md`. يجب مراجعة المصدر وتواريخ الترحيل ومطابقة السندات قبل اختيار أي طريقة استيراد.

## ترتيب التثبيت

1. أخذ نسخة احتياطية من Supabase قبل تحديث الدوال.
2. تشغيل **الملف الواحد فقط**: `database/Maria-CFO-Web-v1.0.11-PRICING-REPAIR.sql` من Supabase SQL Editor. هو ملف تهيئة/إصلاح يشمل متطلبات v1.0.10، ولا يحتاج إعادة تشغيل SQL القديم منفصلًا. لا يحدّث أسعار المواد تلقائيًا أثناء التثبيت.
3. بعد ظهور نجاح SQL، رفع كل ملفات ZIP إلى الاستضافة مع **الإبقاء على config.js القديم كما هو**.
4. تحديث المتصفح تحديثًا قويًا وتأكيد Web v1.0.11.
5. التجربة أولًا على مادة سعرها صفر، ومادة سعرها معلوم، ثم تجربة اعتماد التسعير وتغيير الصرف واختيار «عدم التحديث» ومراجعة أن السعر الصفري بقي غير محدد.
6. تجربة صفحة الصور بأكثر من بند داخل نافذة طويلة، ومراجعة أن الصورة تبقى ظاهرة عند تمرير البنود، ثم فتح نافذة المراجعة دون نشر فاتورة حقيقية أثناء الاختبار الأول.

## حدود الاختبار

اختبارات JavaScript ثابتة ووحدات محلّية؛ لا يوجد اتصال بـ Supabase الحية أو خدمة OCR الخارجية في بيئة البناء. لا تنشر عمليات محاسبية حقيقية قبل اختبار الترحيل على البيئة التي تستخدمها.
