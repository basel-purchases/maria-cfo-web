# Maria CFO Web v1.0.19 — الفواتير والموردون

## ماذا تغيّر؟

1. **إجمالي فاتورة الشراء:** يظهر في التفاصيل مجموع البنود قبل الخصم، إجمالي خصومات البنود، المجموع النهائي، ومجموع كل سطر؛ ويظهر حساب مباشر لإجمالي السطر أثناء إضافة المادة أو تعديلها.
2. **تعديل الفاتورة في أي وقت ضمن الضوابط المالية:** يمكن تعديل رقم الفاتورة، التاريخ، المورد، العملة، والمادة والوحدة والكمية وسعر الوحدة والخصم لأي بند. ويمكن إضافة البنود أو حذفها. مسودات الفواتير تتغير في مكانها. الفاتورة المنشورة تُصحَّح عبر معاملة SQL واحدة: تنشأ نسخة منشورة بديلة، يُسجل عكس مخزون الفاتورة القديمة، ويُحتفظ بالنسخة السابقة وسجل تدقيق التعديلات. بعد الحفظ تُعرض النسخة الجديدة.
3. **حماية الدفعات:** لا تُنشأ دفعة جديدة ولا تُمسح الدفعات المسجلة أثناء التصحيح. إذا كانت على الفاتورة دفعات مخصصة، تنتقل إلى الفاتورة البديلة فقط مع بقاء المورد والعملة وعدم انخفاض الإجمالي المصحح عن المدفوع وعدم تغيّر سعر الصرف عند وجود تخصيصات. غير ذلك يُلغى التصحيح بالكامل وتظهر رسالة توضيحية.
4. **اقتراح المورد:** عند كتابة حرف واحد أو أكثر في اسم المورد تظهر الأسماء الموجودة (مع تسامح في أشكال حرف الألف). ويمكن الكتابة لإضافة مورد جديد.
5. **ثبات النوافذ:** لا تُغلق نوافذ الحوار بالنقر خارجها. يمكن إغلاقها بالزر × أو إلغاء أو Escape، دون إغلاقها أثناء تنفيذ الحفظ.
6. **فاتورة مباشرة للمورد:** زر «فاتورة جديدة» في إجراءات جدول الموردين وزر مماثل داخل ملف كل مورد، يفتح نافذة فاتورة باسم المورد المحدد، ثم يعرض تلقائيًا قائمة المواد التي اشتراها منه سابقًا مع تحديد عدة مواد وكمية ووحدة وسعر وخصم لكل بند. إذا لم تكن له مشتريات سابقة، تظهر نافذة إضافة مادة عادية.
7. **ملف المورد وإحصائياته:** من زر «الملف والإحصائيات» يظهر ملخص الفواتير السارية، مجموع المشتريات والمدفوعات المخصصة والرصيد لكل عملة على حدة، ومسودات الفواتير والملغاة؛ ثم تبويبات الفواتير وبنودها التفصيلية، المواد والكميات والأسعار، حركات مخزون المواد، ودفعات المورد وتخصيصاتها. يوجد بحث وتصدير للجداول المهمة. كشف الحساب المستورد يظل مرجعيًا منفصلًا عن العمليات الفعلية.

## تثبيت الإصدار — الترتيب مهم

1. خذ **نسخة احتياطية صحيحة قابلة للاستعادة** من Supabase قبل تحديث العمليات المحاسبية، ولا تعتمد تصدير CSV تشخيصيًا كنسخة احتياطية.
2. على نفس مشروع Supabase الحالي افتح **SQL Editor** ونفّذ ملف:
   `database/Maria-CFO-Web-v1.0.19-Purchase-Revisions-Supplier-Insights.sql`.
   تأكد أنه انتهى بنجاح ولم يُظهر خطأ. يُضيف جدول تدقيق ودالتَي RPC؛ **لا يحذف بيانات التشغيل ولا يصفّرها**.
3. ارفع **كل محتويات ZIP** إلى الاستضافة بدل النسخة القديمة مع الحفاظ على `config.js` الموجود مسبقًا؛ هذا الملف غير موجود داخل ZIP الجديد لأنه يحتوي إعدادات الاتصال. لا تستخدم ملف `config.js` من مشاركة غير موثوقة ولا تنشر مفاتيح سرية.
4. حدّث صفحة المتصفح تحديثًا قويًا لتجاوز كاش JavaScript وCSS، وتحقق أن الواجهة تُظهر `Web v1.0.19`.
5. جرّب إنشاء فاتورة مسودة لمورد موجود؛ افتح قائمة مواده السابقة، عدّل مادة أو كمية وتحقق من إجمالي السطر والفاتورة. بعدها اختبر **فاتورة منشورة غير مدفوعة** بتغييرٍ صغير وتحقق من وجود رابط النسخة السابقة والمخزون والتقرير. اختبر حالة الدفعات المخصصة في بيئة اختبار/نسخة قاعدة تجريبية قبل اعتمادها في العمل الفعلي.

## حدود مهمة ومراجعات مالية

- لا يمكن تحرير الفواتير التاريخية المرجعية المستوردة وكأنها فواتير مشتريات فعلية. الفواتير الملغاة أو التي استُبدلت بفاتورة مصححة **للقراءة فقط**؛ افتح آخر نسخة للتعديل.
- **لا تحذف كل بنود فاتورة منشورة:** استخدم «إلغاء الفاتورة» الذي ينشئ عكسًا للمخزون، بشرط معالجة أي دفعات مرتبطة بها أولًا.
- تحويل عملة الفاتورة لا يحوّل أسعار بنودها آليًا. يجب مراجعة أسعار المواد والعملة والصرف قبل اعتماد التصحيح.
- «حركة مخزون مواد المورد» تعرض **كل حركات المواد التي سبق شراؤها من المورد**، بما فيها استهلاك تلك المواد وتسويات ومشتريات من موردين آخرين؛ ليست كلها مشتريات هذا المورد، وتظهر تسمية المصدر داخل الجدول.
- الأرصدة المستوردة من نظام خارجي لا تُجمع مع الأرصدة المحاسبية المباشرة. لا تُجمع الليرة والدولار في رقم واحد.
- قائمة مواد المورد السابقة تأتي من فواتير شراء منشورة غير ملغاة، وليست من فواتير المورد المرجعية التاريخية.
- تعديل فاتورة منشورة مع تخصيصات دفع قد يُرفض لحماية مديونية المورد أو سعر الصرف؛ لا تحاول تجاوزه بتعديل مباشر لصفوف قاعدة البيانات.
- **لم يُنفذ ملف SQL على قاعدة Supabase الحية للمستخدم، ولم يُختبر ترحيل فواتير مدفوعة فعليًا.** الاختبارات الآلية محلية، وتشمل تغطية حسابية وفحص ارتباط الواجهات والدوال، ولا تحل محل تجربة تشغيلية ومعاملة فعلية على نسخة آمنة.

## ملفات التحديث

- الكود كاملًا: `index.html`, `assets/`, `js/`, `database/`, `tests/` وكل الملفات الأصلية غير السرية.
- ترحيل قاعدة البيانات: `database/Maria-CFO-Web-v1.0.19-Purchase-Revisions-Supplier-Insights.sql`.
- وظائف مساعدة جديدة: `js/purchase-workflow-v119.js` و`js/supplier-suggest-v119.js`.
- الاختبارات الجديدة: `tests/v119-purchases-supplier-activity.test.mjs`.

**قرار تأجيل التصفير:** لم يتم تصفير أي بيانات، ولم يُنشأ أو يُشغّل سكربت تصفير جديد. بقيت ملفات SQL التاريخية في `database/` لأغراض التوثيق فقط. لا تُشغّل الملفات التي تحتوي RESET.
