# Maria CFO Web v1.0.29 — تحسين مسير الرواتب والدفع الجماعي

الإصدار الأساسي: v1.0.28. هذه حزمة كاملة، دون `config.js`. لا تغيّر أو تصفّر البيانات التاريخية.

## التغييرات

1. **ملاحظة الشهر الأخير:** يظهر الرمز الداخلي `FINAL_MONTH_AUTO_V123:2026-12-03` للمستخدم كعبارة عربية «راتب شهر انتهاء الخدمة محسوب تلقائيًا حتى 03/12/2026». يبقى الرمز الداخلي نفسه دون تغيير للمراجعة المحاسبية.
2. **الأشهر:** ترتيب الأشهر في مرشح الرواتب تنازليًا (كانون الأول إلى كانون الثاني)، والسنوات الأحدث أولًا، مع إبقاء الشهر المختار ظاهرًا.
3. **زر «دفع الكل»:** يفتح نافذة تحتوي رواتب الموظفين المعتمدة غير المدفوعة في الشهر المختار مع خانات لاستثناء موظف أو أكثر. تعرض النافذة العدد والمبالغ المجملة بحسب العملة، دون جمع USD وSYP. يشمل الدفع الراتب المتبقي عند وجود دفع جزئي سابق. زر الدفع ينفذ RPC واحدة، ومعاملة PostgreSQL واحدة: إمّا تصرف جميع الرواتب المختارة وتسجل في الصناديق، وإمّا تفشل العملية كلها دون دفعات جزئية.
4. **ملاحظات السلف والمكافآت:** عند تمرير الفأرة أو التركيز على المبلغ يظهر اسم الموظف وتفاصيل المعاملات المرتبطة بالمسير من قاعدة البيانات، دون افتراض ملاحظات غير مسجلة.
5. **سبب المكافأة والخصم والإضافة اختياري:** في المكافأة تظهر قيمة افتراضية «بدون سبب»؛ وفي نافذة خصم/إضافة الراتب يمكن ترك النص فارغًا. للحفاظ على شرط `reason NOT NULL` في قاعدة البيانات التاريخية دون تغييره، يسجّل البرنامج «لم يُذكر سبب» عند عدم إدخال سبب. تاريخ الاستحقاق والمبلغ أو عدد الساعات يبقون إلزاميين. سبب إلغاء حركة سابقة يبقى إلزاميًا لأن الإلغاء إجراء تدقيقي مختلف.

## التثبيت

1. خذ نسخة احتياطية قابلة للاستعادة من Supabase؛ لا تغيّر بيانات الموظفين أو الصناديق يدويًا.
2. تأكد من تطبيق ملفات SQL لجميع الترحيلات السابقة حتى v1.0.28، ثم نفذ `database/Maria-CFO-Web-v1.0.29-Payroll-Bulk-Payment-Explanations.sql` أولًا **على نسخة اختبار** وأجرِ استعلام `database/Maria-CFO-Web-v1.0.29-VERIFY-READONLY.sql`.
3. ارفع **جميع** ملفات الحزمة v1.0.29 مع الحفاظ على `config.js` الموجود في الاستضافة، وامسح الكاش أو حمّل بقوة.
4. اختبر مكافأة دون سبب، وخصم ساعات دون سبب، ودفع مسير تجريبي به ثلاثة موظفين مع استثناء واحد. تأكد من الدفع فقط للمختارين، وتسجيل حركة صندوق واحدة لكل دفعة وعدم تكرارها عند محاولة إعادة الإرسال.
5. لا تطبق SQL على الإنتاج ولا تصرف رواتب حقيقية قبل نجاح اختبار عملي على قاعدة تجريبية مماثلة؛ لم يُختبر ترحيل v1.0.29 في PostgreSQL حقيقي ضمن بيئة إعداد الحزمة.

## قيود مهمة

- الدفع الجماعي يشمل **بنود المسيرات المعتمدة والجاهزة للدفع فقط**؛ ولا يعتمد المسودات أو يصرف أجرًا يوميًا غير جاهز بمجرّد الضغط على الزر.
- عند انقطاع الاتصال بعد إرسال الدفع، **حدّث كشف المدفوعات أولًا** قبل أي إعادة محاولة؛ قد تكون المعاملة نفذت بنجاح ولم تظهر الاستجابة.
- ملف SQL الجديد يضيف دالتي `pay_approved_salaries_bulk_v129` و`payroll_item_explanations_v129` ولا يغير سجل الدفع الفردي ولا يعيد كتابة أسباب الحركات القديمة.
- تحديث جعل السبب اختياريًا في واجهة إدخال الحركات **لا يحتاج إلى تعديل مستقل لقاعدة البيانات**؛ يستخدم النص المحايد «لم يُذكر سبب» إذا تركه الموظف فارغًا.
