# Maria CFO Web — الإصدار v1.0.9
## تحسين قراءة الأرقام المكتوبة يدويًا في فواتير الشراء
**نقطة الانطلاق:** الحزمة الكاملة v1.0.8. **نوع التغيير:** Frontend/JavaScript فقط، **من دون SQL جديد** و**من دون تعديل config.js**.

### سبب المشكلة

الأرقام التي تعيدها خدمة OCR.space Engine 3 ليست نصًا خامًا مضمونًا: قد يقرأ المحرك الرقم المكتوب يدويًا على صورة خاطئة (مثل الخلط بين الصفر العربي ٠ والخمسة ٥، أو بين أشكال ٢ و٧ و٣). تحويل Unicode في JavaScript كان صحيحًا، لكن لا يمكن استرجاع الرقم الأصلي بعد أن تغيّره الخدمة بصريًا. بعض الفواتير تُستخرج في جداول Markdown بلا عنوان للأعمدة، فيفقد النظام دور الرقم (كمية/سعر/إجمالي) رغم ظهور قيمة نصية.

### 1) معالجة بصرية للأرقام

- عندما يحدد المستخدم منطقة «البنود والإجمالي»، تُجهّز تلك المنطقة بمسار خاص للأرقام المكتوبة: تكبير مع تنعيم مناسب، تخفيف لون الورق والظلال المحلية، وإبراز الحبر وخصوصًا الأزرق. لا تُحذف النقاط الصغيرة ولا تُطبّق عملية تصحيح شكل رقم ٢/٣/٥ بالتخمين.
- بقيت مناطق الاسم والرقم وغيرهما على تجهيز الصور القديم، ولم تُستبدل الخدمة أو تُشغّل محركات جديدة. يستمر Engine 3 وحده.
- أضيف زر **«منطقة الأرقام»** لتحديد موضع الأرقام بدقة أعلى عند الرغبة في تدقيق إضافي. لا يؤدي إنشاء التحديد إلى طلب OCR إضافي تلقائيًا.

### 2) تكبير الأرقام بلا خدمة أو كلفة

اضغط «تكبير الأرقام» لعرض المنطقة المحددة بعد المعالجة في نافذة كبيرة. المعالجة على جهاز المستخدم فقط؛ لا تطلب OCR ولا تنشر بيانات.

### 3) تدقيق الأرقام — بطلب صريح

- بعد الاستخراج الأول يمكن ضغط **«تدقيق الأرقام · طلب إضافي»**. يظهر تأكيد صريح لأن هذا الطلب يُحتسب من حصة Engine 3 في Supabase.
- تستخدم القراءة الثانية «منطقة الأرقام» إن حُددت، وإلا منطقة «البنود والإجمالي»، وإلا الصورة كاملة.
- النتيجة **للمقارنة فقط**: لا تغيّر كمية أو سعرًا سبق للمستخدم تصحيحه، ولا تعيد حفظ الفاتورة أو حركات المخزون تلقائيًا.
- إذا طابق عدد أسطر القراءة الثانية عدد البنود، تُعرض أرقامها بجانب البند بمصدر «التدقيق»، مع زر «كمية» أو «سعر» لنقل أي رقم يختاره المستخدم إلى الحقل المقصود. يُعاد طلب تأكيد المراجعة لذلك البند بعد النقل.
- إذا اختلف عدد الأسطر، لا يربط البرنامج الأرقام بالبنود خشية إسناد سعر إلى مادة خاطئة؛ النص الثاني ظاهر فقط داخل زر النص الخام الاختياري.
- حتى مع تطابق القراءتين، **لا توجد شهادة دقة**؛ فقد يكرر المحرك الخطأ نفسه.

### 4) جداول دون أسماء أعمدة

يدعم الآن الصورة التي ولّد OCR منها النص:

```
| ٦٥٠٠ | ضبا 2 + مثال كل | ٦٥٠٠ |
| ٤٤٥٠ | اسم عارف | ٤٧٧ |
| ١٩٠ | لفة حب | ١٢٢٠ |
```

ينشئ ثلاثة بنود بأسمائها كما أعادها المحرك، ويعرض الأرقام مع موضعها (العمود الأيسر/الأيمن)، لكنه **لا يخترع دور هذه الأرقام** ولا يضعها آليًا في السعر أو الكمية. يجب مراجعة الصورة واختيار الدور الصحيح للأرقام أو كتابتها يدويًا. كما يبقى اسم المادة قابلًا للتصحيح والربط بالأسماء الثانوية.

### 5) الحماية المحاسبية والحدود

- لا يُسمح بحفظ فاتورة مع كميات أو أسعار ناقصة. وأي بند مستخرج غير مؤكد يطلب مراجعة صريحة ووحدة صحيحة قبل الحفظ.
- لم تتغير وظائف الموردين، الصناديق، المنشورات المحاسبية، المشتريات أو مسارات RPC.
- لا ضمان لدقة 100%: دقة محرك OCR نفسه تعتمد على جودة التصوير والخط والتباين. لا ندّعي أن محرك 3 «تعلّم» قواعد جديدة بمجرد تغيير JavaScript.
- لا تُضمَّن مفاتيح OCR أو `config.js` في الحزمة.

### 6) تركيب النسخة

1. حافظ على `config.js` في الاستضافة كما هو.
2. ارفع جميع الملفات من ZIP الكامل **v1.0.9** بدل النسخة السابقة، مع استبدال ملفات المشروع باستثناء `config.js`.
3. حدّث المتصفح بقوة وتأكد من ظهور **Web v1.0.9**.
4. لا تحتاج أي ترحيل SQL جديد لهذا الإصدار، بشرط تطبيق SQL الخاص بالأسماء الثانوية v1.0.6 سابقًا.
5. لاستخراج جديد: حدد منطقة البنود، ثم اضغط «استخراج». للتدقيق: حدد «منطقة الأرقام» إذا أمكن، ثم «تكبير الأرقام»، ثم «تدقيق الأرقام · طلب إضافي» عند الحاجة.
6. لاختبار فاتورة موجودة، يمكنك استخدام «تحديث البنود من النص المحفوظ» **دون استهلاك طلب OCR**؛ تأكد أولًا لأن هذا يمسح تعديلات البنود الحالية بعد الموافقة. هذا الزر لا يعيد قراءة الصورة بصريًا. تدقيق الأرقام هو زر منفصل يستهلك طلبًا إضافيًا.
7. جرّب فاتورة غير منشورة وراجع الأرقام والوحدات والإجماليات قبل اعتماد حفظها.

### 7) الاختبارات

- 327 اختبارًا إجمالًا: **320 ناجحًا، صفر فشل، 7 متروكة** في Node.js.
- تشمل اختبارات v1.0.9 مثال Markdown الذي أُرسل بالفعل، والأرقام العربية والفارسية، وصون صفوف المبالغ وعدم تعديل الكميات/الأسعار دون اختيار المستخدم، والحفاظ على نقطة الصفر الصغيرة في معالجة الصورة.
- **لم** يجرِ تشغيل خدمة OCR.space على الصورة المرسلة ولا اتصال Supabase الحي. تعذر إكمال فحص Chromium التفاعلي في بيئة البناء؛ فلا نعدّ اختبار المتصفح/الخدمة ناجحًا.
