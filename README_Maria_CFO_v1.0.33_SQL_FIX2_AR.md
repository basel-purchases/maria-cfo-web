# Maria CFO v1.0.33 — تصحيح SQL رقم 2

## المشكلة

خطأ PostgreSQL عند السطر 255: `syntax error at end of input` داخل دالة `public.v133_menu_merge` أثناء التحقق من الحد الأقصى للأسماء الثانوية. كان شرط `IF` يجمع استعلام `count(*)` مع تعبير `CASE ... THEN` واستعلام `NOT EXISTS`، مما أدى إلى خطأ في تفسير الشرط.

## التصحيح

فصل حساب العدد إلى استعلامين صريحين: عدد الأسماء الموجودة، وهل اسم الوجبة المصدر موجود بالفعل كاسم ثانوي. إذا كان يلزم إضافته، يُزاد العداد بمقدار واحد. بعدها يتحقق شرط `IF v_existing_alias_count > 40` من الحد الأقصى. لم يتغير منطق الدمج أو بقية الوظائف.

## خطوات الاستخدام

1. احتفظ بنسخة احتياطية، واختبر على قاعدة تجريبية مطابقة للإنتاج.
2. في Supabase SQL Editor، افتح الملف `Maria-CFO-Web-v1.0.33-Menu-Merge-And-Inventory-Only-Completion-FIX2.sql` كاملًا، لا تحدد جزءًا منه فقط.
3. نفّذ النص كاملًا **بدل SQL v1.0.33 القديم**، بعد أن تكون ترحيلات v1.0.32 مثبتة بالفعل.
4. نفّذ استعلام التحقق الموجود في إصدار v1.0.33 ثم اختبر دمج وجبتين غير مستخدمتين، واستكمال صرف وجبة مجرّبة.
5. إذا جرى تشغيل SQL السابق كمعاملة كاملة `BEGIN...COMMIT` وفشل داخله، فتُلغى أوامره ضمن المعاملة؛ أما إن شُغلت منه أجزاء منفصلة فافحص النتائج قبل الإعادة.

## التحقق المُنجز هنا

- توازن 10 كتل SQL ذات الاقتباس بعلامة الدولار، وفواصل 44 أمرًا رئيسيًا.
- توازن أقواس SQL الخارجي وشروط `IF`/`END IF` داخل الدوال.
- فحص أن شرط `CASE` الإشكالي لم يعد موجودًا.
- **لم أختبر التنفيذ في PostgreSQL/Supabase الفعلي.** قد تظهر مشكلات أخرى مرتبطة ببنية قاعدة البيانات أو البيانات الحية، لذلك لا يُعتبر الفحص الساكن اختبار ترحيل نهائيًا.

لا تتطلب هذه المراجعة إعادة رفع ملفات الواجهة أو تصفير قاعدة البيانات.
