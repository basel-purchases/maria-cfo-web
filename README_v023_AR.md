# Maria CFO Web v0.23 — التسليم الموحد

## التثبيت بالترتيب
1. انسخ قاعدة بيانات Supabase احتياطيًا وخذ نسخة من مستودع GitHub الحالي.
2. على **نسخة اختبار من القاعدة** نفّذ `database/Maria_CFO_Web_v0.23_Migration.sql` مرة واحدة. الملف موحد للدفعتين ويعمل داخل معاملة BEGIN/COMMIT. لا تشغّل ملفات `Batch1_DRAFT` أو `Batch2` منفصلة.
3. اختبر على بيانات وهمية: الأجر اليومي لموظفين في نفس اليوم، الأجر المقطوع مع السلف، الإجازة، خصم أوردر ورسومه، ضيافة، سحب النشر، تحويل صندوق إلى العام، والمصروفات. راجع رصيد الصندوق والمخزون والتقارير.
4. إذا نجحت اختبارات قاعدة الاختبار، اتبع إجراء نشر الترحيل إلى الإنتاج ثم انسخ جميع ملفات الموقع من ZIP إلى المستودع، مع إبقاء `config.js` و `.git` و `.github` وإعدادات GitHub كما هي. لا تحذف الملفات القديمة أولًا.
5. حدّث الموقع وتأكد من ظهور `Web v0.23`. لا تعِد نشر `assistant` أو `ocr-space` دون حاجة.

## الوظائف
- أربع أنواع أجور: ساعي، يومي، شهري، مقطوع. المقطوع يُسجل بدفعة مستقلة في صندوق الرواتب دون اعتماد دوامه، ويُحفظ تاريخيًا مع الخصم من السلف.
- سجل دفعات برواتب بفلتر يوم/شهر/سنة وصفحات؛ صفحة سلف ذات حالات وأقساط؛ إجازات مدفوعة بحد سنوي من الإعدادات.
- ضبط ساعات الدوام الأساسية والإضافي؛ قسم الأساسيات لعدّ الكراسي والطاولات والأواني وحدود التنبيه.
- تصنيفات المواد والأصول والوجبات من الإعدادات وفلاتر بالأقسام.
- الدفعة الأولى محفوظة: تفاصيل الأوردر والضيافة والخصومات والرسوم، المصروفات، الصناديق، المخزون والتصدير.

## محاسبة وحماية
- لا تنفذ معالجة مبيعات أو سحب نشر أو تصفير صندوق في الإنتاج قبل اختبار مطابق: جميع الحركات المالية عبر RPC، ولا تُحذف سجلات منشورة.
- `net_total_original` و`net_total_base` يُحدّثان معًا للعملة والسعر التاريخي. الضرائب المحصلة تظهر منفصلة عن الإيراد في الإحصائيات.
- حماية رفض نفس الأجر اليومي مرتين مع السماح لموظفين مختلفين باليوم نفسه.
- تصنيف أو أجر مقطوع جديد لا يغير السجلات التاريخية القديمة.
- ملف ZIP لا يحتوي `config.js` أو ملفات Git الخاصة بك.

## قيود الاختبارات
فحوص JavaScript واختبارات منطق محلية فقط، وليست تجربة فعلية لقاعدة Supabase الحية. راجع تعريفات الجداول والدوال والسياسات في قاعدة الاختبار قبل تشغيل الترحيل الإنتاجي.
