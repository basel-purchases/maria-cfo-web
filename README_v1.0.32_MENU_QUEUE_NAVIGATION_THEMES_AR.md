# Maria CFO Web v1.0.32 — ترتيب الواجهة وتسوية المبيعات

**الإصدار الأساسي:** v1.0.31. هذا الإصدار يستكمل عمل v1.0.31 ولا يطلب تصفير قاعدة البيانات، ولا تغيير فاتورة أو قبض أو جرد سابق.

## التغييرات

1. **تسوية تكاليف المبيعات:** ترتيب بحسب اسم الوجبة على مستوى قاعدة البيانات، قبل تقسيم النتائج إلى صفحات. يمكن البحث داخل الصفحة الحالية. تظهر الحالة مكتملة باللون الأخضر.
2. **صنف غير موجود في المنيو:** زر «إضافة إلى المنيو» يتيح (أ) إنشاء وجبة جديدة فعلًا في المنيو، أو (ب) إضافة الاسم كاسم ثانوي لوجبة موجودة. يربط الإجراء **جميع بنود المبيعات المعلقة المطابقة لنفس الاسم** بالوجبة المقصودة، دون تعديل المبيعات الأصلية أو قبضها مجددًا.
3. **صنف موجود بلا مكونات:** يظهر زر «إكمال الوصفة»، وينتقل إلى قائمة المنيو مع البحث عن الصنف مسبقًا. بعد إدخال مكونات الوصفة يظهر خيار «استكمال الصرف» عند العودة إلى التسوية.
4. **صنف مكتمل:** زر «استكمال الصرف» يستعمل آلية v1.0.31 الموجودة، التي تحترم آخر جرد معتمد وتمنع الخصم المكرر.
5. **ترتيب القائمة الجانبية:** الصفحة الرئيسية، الإدخالات الأساسية، التشغيل اليومي، الموظفون والرواتب، الحفلات، المساعد الذكي، الإحصائيات، أخرى، الإعدادات. تحتوي الإدخالات الأساسية على الجرد وسجل الجرد والاستيراد، بينما الصور موجودة في «أخرى». تظل روابط الأقسام القديمة متاحة.
6. **الإحصائيات:** تبويبات مستقلة؛ يتم تحميل التبويب المفتوح فقط عند الطلب، وتُحفظ نتائجه مؤقتًا داخل الصفحة حتى الضغط على «تحديث التبويب الحالي».
7. **رمز 📦:** عداد لعدد المبيعات التي أصبحت لها وصفات ويمكن مراجعة تسويتها، وليس رسائل. الضغط عليه يفتح نافذة توضيح وزرًا للوصول إلى الصفحة أو تحديثها إذا كانت مفتوحة.
8. **خمسة ستايلات:** 1 الكلاسيكي، 2 راقٍ وأنيق، 3 أزرق هادئ، 4 أخضر طبيعي، 5 رملي دافئ. يُحفظ الاختيار محليًا في المتصفح دون التأثير على قاعدة البيانات.
9. **الإعدادات:** تبويب تصنيفات واحد، يتفرع إلى تصنيفات المواد والمنيو/الأساسيات والمصروفات. تبويب «حول البرنامج» يعرض الاعتماد والتواصل: باسل صليبي، 0996202134، basel.slaby@gmail.com.
10. **رقم الإصدار:** معروض في أعلى الصفحة وأسفل القائمة الجانبية بصورة دائمة.

## التثبيت الآمن

1. احتفظ بنسخة احتياطية من قاعدة البيانات ومن ملفات v1.0.31 الحالية.
2. **أولًا** نفّذ ملف `Maria-CFO-Web-v1.0.32-Sale-Queue-Menu-Link-FIX.sql` على قاعدة **تجريبية** مثبتة عليها v1.0.31. بعد نجاح الاختبار، نفّذه على الإنتاج وفق إجراء النسخ الاحتياطي المعتاد. هذه الإضافة تنشئ دوال الربط وتحدث استعلام عرض التسوية فقط.
3. نفّذ استعلام `Maria-CFO-Web-v1.0.32-VERIFY-READONLY.sql` للتأكد من وجود الدوال الثلاث بعد التحديث.
4. ارفع ملفات الحزمة الكاملة v1.0.32 فوق ملفات البرنامج؛ **لا تستبدل ولا تحذف `config.js` الموجود على استضافتك**.
5. امسح ذاكرة الموقع عند الحاجة أو استخدم تحديثًا قويًا، وتحقق من ظهور **Web v1.0.32**.

## اختبار سيناريو القهوة

1. افتح «التشغيل اليومي > تسوية تكاليف المبيعات»؛ ستظهر صفوف القهوة القديمة بحسب اسمها لا بحسب رقم الأوردر.
2. إذا كانت القهوة غير مربوطة بالمنيو: اضغط «إضافة إلى المنيو» ثم اختر إنشاء وجبة أو اسم ثانوي.
3. يجب إنشاء وجبة واحدة أو إضافة alias واحد فقط، ثم ربط جميع صفوف القهوة **المعلقة** المطابقة باسم البيع الأصلي.
4. ينتقل البرنامج إلى صفحة المنيو **مفلترة بالقهوة**. أدخل المكونات في إدارة الوصفة.
5. ارجع إلى التسوية؛ ستجد «استكمال الصرف» للصفوف القابلة للصرف. لا يكرر هذا الإجراء القبض أو إضافة الأوردر.
6. عند اختبارها، تحقق من أن بند بيع بتاريخ الجرد المعتمد أو قبله لا يخفض الرصيد مرة أخرى.

## ضوابط مهمة

- الدمج في الربط يحدث للمبيعات المعلقة **غير المرتبطة** فقط؛ إذا كان هناك تطابق ملتبس بين أكثر من وجبة، لن يختار النظام الوجبة تلقائيًا، ويترك القرار للمحاسب.
- لا يوجد أي إجراء جماعي يغيّر المبيعات أو الصندوق داخل ملف SQL الجديد. دوال الربط تعدل مرجع المنيو لصفوف قائمة التسوية المعلقة فقط. الصرف المخزني لاحقًا يتم عبر منطق v1.0.31 الحالي.
- ما زالت حالات «مراجعة صرف سابق» تحتاج مراجعة يدوية، ولا يحاول النظام إعادة صرفها آليًا.
- لا تُنفّذ SQL v1.0.31 مجددًا ولا تصفّر قاعدة البيانات لغرض هذا الإصلاح.

## الاختبارات وحدود التحقق

- اختبارات Node المحلية: **520 إجمالًا؛ 513 ناجحًا، 7 متجاوزة، 0 فشل** (بعد تحديث توقعات التنقل القديمة، وإضافة اختبارات v1.0.32).
- تم ربط واستيعاب **103 وحدات JavaScript محلية** دون تصديرات مفقودة باستخدام فحص وحدات ESM ثابت.
- **لم يتم تنفيذ SQL على PostgreSQL أو Supabase حقيقية**، ولا يمكن الجزم بنجاح الترحيل حتى تنفيذه على قاعدة اختبار.
- تعذر إكمال تشغيل Chromium في بيئة التوليد بسبب حظر الاتصال المحلي/الافتراضي؛ لا يُعد هذا اختبار تشغيل بصري ناجحًا.
