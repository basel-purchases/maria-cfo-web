# Maria CFO Web v0.11

نسخة اختبار تركز على تحسين تحليل صور فواتير الشراء ومراجعة بيانات الذكاء الاصطناعي قبل الحفظ.

## قبل الاختبار
1. لا يوجد Migration جديد خاص بـ v0.11.
2. إذا لم تكن قد شغّلت تحديث مشتريات v0.10 بنجاح، استخدم الملف المصحح الموجود داخل `database/Maria_CFO_Web_v0.10_Migration.sql`.
3. استبدل ملفات المشروع فوق `Maria-CFO-Web-Live`.
4. لا تستبدل `config.js`؛ هذه الحزمة لا تحتويه أصلًا.
5. حدّث Edge Function باسم `document-ocr` بمحتوى `supabase/functions/document-ocr/index.ts` ثم Deploy.
6. نفّذ `Ctrl + F5` في المتصفح.

## أهم تغييرات v0.11
- تحسين تعليمات OCR لقراءة الأرقام العربية الهندية المكتوبة بخط اليد، مع تنبيه خاص للرقم `٢` الذي قد يشبه 7 إنكليزيًا معكوسًا.
- تطبيع الأرقام العربية/الفارسية إلى قيم رقمية قبل إرسالها للموقع.
- تطبيع التاريخ إلى `YYYY-MM-DD` حتى يظهر بشكل صحيح في حقل التاريخ.
- المورد، رقم الفاتورة، التاريخ، العملة، وإجمالي الفاتورة المقروء أصبحت كلها قابلة للتعديل.
- اسم المادة المقروء أصبح قابلاً للتعديل فورًا.
- المادة المرتبطة في Maria CFO، الوحدة، الكمية، سعر الوحدة، وإجمالي السطر كلها قابلة للتعديل.
- إذا عُرف إجمالي السطر ولم يُعرف سعر الوحدة، يحسب الموقع سعر الوحدة من الإجمالي ÷ الكمية.
- إذا عُدلت الكمية أو سعر الوحدة يعاد حساب إجمالي السطر، وإذا عُدل إجمالي السطر يعاد حساب سعر الوحدة.
- عند حفظ مراجعة OCR يتم تحديث بيانات رأس الفاتورة ثم إضافة البنود المحددة.
- يظهر إجمالي البنود المحددة أثناء المراجعة للمقارنة مع إجمالي الفاتورة المقروء.

## تحديث v0.12
يتطلب v0.12 تشغيل `database/Maria_CFO_Web_v0.12_Migration.sql` مرة واحدة وإعادة نشر `document-ocr` من الملف الموجود داخل `supabase/functions/document-ocr/index.ts`.

أصبح تحليل الصور يعمل كمهام خلفية محفوظة في قاعدة البيانات، لذلك لا يحتاج المستخدم للبقاء في الصفحة بانتظار Gemini.
