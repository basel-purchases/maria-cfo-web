# Maria CFO Web v0.2

نسخة الويب الثانية من Maria CFO، ومهمتها تثبيت تجربة الاستخدام قبل العودة إلى تطبيق الهاتف.

## أهم تغييرات v0.2

- توسيط هوية Maria CFO في شاشة تسجيل الدخول.
- إزالة البريد الإلكتروني وزر الخروج من الشريط اليومي؛ تسجيل الخروج أصبح داخل الإعدادات فقط.
- زر رجوع واضح في جميع الصفحات الداخلية.
- الأقسام الرئيسية تبقى متاحة دائمًا من القائمة الجانبية.
- تحسين تمييز القسم الحالي حتى عند الدخول إلى صفحة فرعية.
- منع اقتراحات/Autofill المتصفح المزعجة في نموذج إضافة المادة قدر الإمكان.
- توضيح الفرق بين **الرصيد الحالي** و**المستوى المستهدف للمخزون**.
- إضافة حقول اختيارية عند تعريف المادة:
  - الرصيد الموجود الآن.
  - آخر سعر معروف للوحدة.
  - المستوى المستهدف للمخزون.
- الرصيد الافتتاحي يسجل كحركة مخزون قابلة للتتبع بدل تعديل الرصيد مباشرة.
- إمكانية تعديل الرصيد والسعر المرجعي لاحقًا من صفحة المواد نفسها.
- عرض `TRAY` بالعربية باسم **سفط**.
- المساعد الذكي يعيد المحاولة حتى 3 مرات عند الأخطاء المؤقتة، ولا يعرض 502 للمستخدم.

## التشغيل

المشروع Static Site ولا يحتاج Node أو Build.

1. افتح `config.js`.
2. ضع `supabaseUrl` و`supabasePublishableKey`.
3. لا تضع أبدًا Service Role أو `GEMINI_API_KEY` في الموقع.
4. شغّل الموقع عبر HTTP server أو GitHub Pages.

مثال محلي:

```bash
python -m http.server 8080
```

ثم افتح:

```text
http://localhost:8080
```

## Supabase

الموقع يستخدم نفس Supabase الخاص بالتطبيق ونفس RLS/RPCs.

### الرصيد الافتتاحي للمادة

عند إدخال رصيد موجود فعليًا، يستخدم الموقع RPC `record_inventory_movement` بنوع `opening`، حتى يبقى سجل المخزون قابلاً للتدقيق.

### السعر المرجعي الأولي

السعر اختياري. يحاول الموقع حفظه كمرجع للمادة، والفواتير الفعلية اللاحقة تصبح المرجع الأساسي للأسعار.

## المساعد الذكي

الملف:

```text
supabase/functions/assistant/index.ts
```

يتضمن:
- 3 محاولات عند 408/429/5xx ومنها 502.
- Timeout لكل محاولة.
- Backoff بين المحاولات.
- رسالة عربية مفهومة للمستخدم عند الفشل النهائي.
- الخطأ التقني يبقى في Logs.
