# Maria CFO — Web v0.17 | الوكيل التشغيلي الآمن

**حزمة كاملة** لتحديث موقع GitHub Pages الحالي من Maria CFO Web v0.14.0 إلى **v0.17**. تحتفظ بكل ملفات الواجهة وOCR ووظائف التشغيل التي كانت في v0.14، مع استبدال الملفات المطابقة عند النسخ. **لا تتضمن** `config.js` أو `.git` أو `.github` أو أي مفتاح API. **لا تحذف** ملفات المستودع الموجودة قبل النسخ.

## ماذا يقدم هذا الإصدار؟

- **المساعد وكيل أفعال محددة:** يقرأ إحصائيات الموقع وبيانات المالك ويستطيع إدخال موظفين جدد بمجرد طلب واضح (مثل: «أضف موظفين: أنس يومي براتب 100، زياد شهري براتب 3000»)؛ يحفظ الحقول الإلزامية بالأسماء المعتمدة في قاعدة البيانات، ويطلب المفقود دون تخمين. يقدر كذلك على إضافة مورد أو مادة (بعد تحديد وحدتها) أو حفلة أو تسجيل دوام، وتجهيز مسودات أوردرات وفواتير حسب المواد/الوجبات الموجودة.
- **الفواتير/الأوردرات المصورة:** إرفاق JPG/PNG/WEBP داخل المحادثة، استخراج الأصناف والكمية والسعر والخصم، عرض جدول قابل للتعديل مع تنبيه انخفاض دقة القراءة، ثم **زر موافقة صريحة لإنشاء مسودة** فقط. النشر المحاسبي يحتاج موافقة أخرى. لن يطابق مادة مجهولة عشوائيًا.
- **الإجراءات النقدية والحساسة:** النشر والصرف والمصروفات تتطلب موافقة في المحادثة على ملخص العملية. التنفيذ النهائي حصريًا عبر RPCs المالية المحمية ولا يكتب مباشرة إلى مخزون أو صندوق. يؤكد المقترح مرة واحدة وله مدة صلاحية 15 دقيقة.
- **مرونة عند فشل Gemini:** محاولة نماذج متاحة بديلة ورسالة سبب مفهومة، مع مسار مباشر لإضافة الموظفين بأمر عربي واضح وقراءات محددة لبيانات المال/المواد/الموظفين حتى إن توقف المزود. عدم توفر المفتاح أو حصته لا يمكن إصلاحه في كود الواجهة وحده.
- **أجر اليومي والساعي:** صفر ساعات فعلية لا ينتج استحقاقًا تلقائيًا، باستثناء `paid_leave` التي يسجلها المدير بوضوح. صفحة الرواتب تعرض ملاحظات مراجعة للأيام المشكوك بها؛ الدفع يمر عبر RPC v0.17 ترفض الأجر اليومي غير المستحق دون تعديل الدفاتر القديمة أو سياسة الشهري.
- **التنقل:** روابط حقيقية لأقسام المشروع من داخل رد المساعد. «جاري الإجابة…» عند المعالجة.

**حدود الوكيل:** ليس AGI عامًا ولا محرر SQL حر. الأدوات المحصورة في الشيفرة هي حدود أمان حقيقية. عمليات مثل تعديل راتب سابق أو إلغاء مستند منشور أو إدارة حجوزات حفلة تفصيلية قد تتطلب إضافة أداة مراجعة لاحقة؛ عند غياب الأداة يصرّح بذلك ولا يدعي التنفيذ. لا يمكن التحقق من اتصال Gemini أو نجاح تحديث Supabase قبل نشر الكود والاختبار الفعلي.

## ترتيب التركيب — مهم جدًا

1. **النسخ الاحتياطية:** احتفظ بآخر Commit في GitHub ونسخة احتياطية من قاعدة Supabase. تأكد من نجاح قاعدة v0.14 في الموقع الحالي.
2. **SQL أولًا:** في Supabase → SQL Editor نفّذ **فقط** `database/Maria_CFO_Web_v0.17_Migration.sql` (أو الملف المنفصل المرفق). هذا التحديث يضيف جدول موافقات المساعد ودوال v0.17 دون تغيير التاريخ المالي. إذا فشل الاستعلام، توقف ولا تنشر الواجهة قبل المراجعة.
3. **نشر دالة المساعد فعليًا:** نشر ملفات GitHub **لا ينشر** Supabase Edge Function. في Supabase Dashboard → Edge Functions → `assistant` استخدم محتوى `supabase/functions/assistant/dashboard-single-file.ts` إذا كنت تعمل من محرر ملف واحد، ثم Deploy، أو انشر مجلد `supabase/functions/assistant` عبر Supabase CLI. راجع `docs/DEPLOY_ASSISTANT_AGENT_V017_AR.md`. **لا تعيد نشر `document-ocr` القديمة** دون داعٍ.
4. **Secrets:** تأكد أن Supabase Secrets تشمل `GEMINI_API_KEY` صحيحًا؛ يمكن ضبط `GEMINI_MODEL=gemini-3.5-flash-lite` اختياريًا. لا تضع المفتاح في JavaScript أو ملف GitHub العام. تحتاج الخطة إلى حدود استخدام المزود.
5. **GitHub Pages:** فك الضغط إلى جذر مستودع الموقع الحالي واستبدل الملفات المتشابهة **دون حذف البقية**. اترك `config.js` و`.git` و`.github` وإعدادات GitHub Pages كما هي. Commit وانتظر النشر.
6. **تحديث المتصفح:** `Ctrl+F5` وتحقق من وجود «Web v0.17» أسفل القائمة، ثم افتح المساعد. نفّذ اختبارات `docs/TEST_ASSISTANT_V017_AR.md` قبل استخدام الأوامر المالية على سجلات حقيقية.

## تدقيق النشر الأولي

- «أضف موظفين: أنس يومي براتب 100، زياد شهري براتب 3000» → يجب إنشاء الموظفين مرة واحدة فقط، دون محاولة إنشاء أسماء متكررة. **استخدم أسماء اختبار جديدة لتجنب تكرار موظفين حقيقيين.**
- اضغط «اختبر Gemini الآن» في رأس المساعد لتجربة استجابة حقيقية؛ إذا تعذر الاختبار تظهر رسالة السبب بدل الاكتفاء بادعاء الجاهزية.
- «ما مبيعات اليوم؟» → تظهر الأرقام من RPC آمنة. لا يُنشئ المساعد أرقامًا من عنده.
- أرسل صورة فاتورة تجريبية → راجع الكمية والسعر والخصم والوحدة. الضغط على «اعتماد وإضافة مسودة» ينشئ مسودة فقط إذا كانت الأصناف موجودة.
- يوم موظف يومي سجّل 0/8 ساعات «دوام كامل»: يجب أن يُعرض كحالة مراجعة لا كأجر مستحق 100. إذا كانت إجازة مدفوعة فعلًا، سجّل `paid_leave` صراحة.
- قبل دفع أجر فعلي، تأكد من اختيار صندوق الرواتب في الإعدادات؛ لا نختبر الدفع الحقيقي على بيانات التشغيل بلا مراجعة.
