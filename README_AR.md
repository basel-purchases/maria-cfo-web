# Maria CFO Web v0.14.0 — واجهة المدير والمستحقات

**الحزمة كاملة لاستبدال ملفات الموقع المنشور من v0.13.2.** لا تشمل `config.js` أو `.git` أو `.github` أو مفاتيح/بيانات دخول.

## ما الجديد؟

- **رواتب اليومي والساعي:** بمجرد تسجيل الدوام تظهر الأجور في قائمة المستحقات المقدّرة. يبدأ الدفع من الزر الموجود بجانب اليوم؛ خادم Supabase ينشئ مسيرًا ماليًا ليوم واحد، يطبق تعديلات الرواتب والسلف عبر الدوال الأصلية، ثم يعتمد ويدفع عبر RPC محمية وحركة نقدية موثقة، في معاملة واحدة.
- **منع تكرار الدفع:** لا يمكن دفع يوم مرتبط بمسير معتمد سابق، ولا اعتماد مسير متداخل لنفس الموظف والفترة. كما تُقفل سجلات الدوام التي دخلت في مسير معتمد.
- **الشهرية:** إنشاء مسير شهري للموظفين الشهريين فقط، ثم مراجعة/تحديث/اعتماد المسودة قبل الدفع. لا يتم خصم نقص الموظف الشهري تلقائيًا.
- **الصندوق:** الإعدادات ← «الرواتب والصناديق» لاختيار صندوق الرواتب؛ لا يسمح بالصرف قبل اختياره.
- **الرواتب التاريخية:** تختفي المستحقات عند التسوية الكاملة، لكنها تبقى في جدول الدفعات التاريخي. يدعم الدفع الجزئي للراتب المعتمد.
- **ألوان ثابتة:** شهري = بنفسجي، يومي = أخضر، ساعي = أزرق في الجداول المتعلقة بالموظفين.
- **التقارير:** تصحيح أسماء معاملات `get_financial_statistics` و`get_home_dashboard`، واستخدام JSON الفعلي المتداخل في بطاقات إحصائية، رسوم الإيرادات، تغير الأسعار، المخزون، الرواتب، الصناديق، فروقات العملات والتنبيهات. لا يدّعي أن الأرباح نهائية إذا كانت تكلفة تاريخية ناقصة.
- **المساعد:** تغيير «جاري المحاولة» إلى «جاري الإجابة».

## التثبيت (الترتيب مهم)

1. خذ نسخة احتياطية من قاعدة Supabase ومن آخر Commit على GitHub.
2. افتح Supabase → SQL Editor والصق الملف **`database/Maria_CFO_Web_v0.14_Migration.sql`** ثم Run لمرة واحدة. يحتوي BEGIN/COMMIT. إذا ظهر خطأ فلا تتابع نشر الموقع قبل معالجة الخطأ؛ لا تحاول حذف سجلات محاسبية.
3. فك الضغط وانسخ محتوياته إلى **جذر** مستودع GitHub الحالي، مع استبدال الملفات المطابقة. **لا تمسح المستودع أولًا، ولا تغير `config.js` أو `.git` أو `.github` أو إعدادات GitHub Pages**.
4. انتظر نشر GitHub Pages ثم حدّث المتصفح `Ctrl+F5`. تأكد من كتابة **Web v0.14.0** أسفل القائمة.
5. افتح **الإعدادات ← الرواتب والصناديق**، اختر صندوقًا نشطًا، واضغط «حفظ صندوق الرواتب».
6. نفّذ الاختبارات المذكورة في `docs/TEST_PAYROLL_ANALYTICS_V014_AR.md` على عمليات اختبار صغيرة معلومة المصدر.

**تنبيه:** ملفات migrations v0.7–v0.13 هي تاريخ المشروع؛ لا تنفذها مجددًا. نفّذ ملف v0.14 فقط إذا كنت تستخدم نسخة قاعدة البيانات التي جرى فحصها في هذا التسليم. إذا كانت قاعدة البيانات تغيّرت بعد آخر Snapshot فقد نحتاج تكييف migration قبل تشغيله.

## حدود هذا الإصدار

- لا توجد قناة اتصال مباشرة بقاعدة بياناتك الحية هنا؛ لذلك اختبارات JS محلية فقط، ونجاح إصدار الرواتب يحتاج تجربة Supabase الفعلية قبل الاستخدام الإنتاجي.
- الأجور غير المعتمدة *تقديرية* وقد تتغير عند الصرف النهائي بسبب السلف/الخصومات/المكافآت. لا تعتبر مصروفًا محاسبيًا معتمدًا قبل إنشاء المسير.
- رصيد راتب معتمد قد يدفع جزئيًا ويبقى في قائمة الأرصدة غير المسددة، مع حفظ جميع دفعاته.
- يستدعي صرف اليوم الواحد حاسبة الرواتب الأصلية ثم يحتفظ ببند الموظف المطلوب فقط؛ لذلك يعتمد على سلامة قاعدة الرواتب الكاملة. لا يُسمح بالنشر إذا فشلت شروط المحاسبة.
- تغيير الدوام بعد اعتماد راتبه يحتاج سير تصحيح/إلغاء مالي موثق، لا تعديلًا مباشرًا.
