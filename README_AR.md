# Maria CFO Web v0.13.2

إصدار كامل للموقع، يحتوي على بقية أقسام المشروع كما كانت في v0.13.1، مع إصلاح إضافة الموظفين، تعديل الدوام، وإنشاء الحفلات. لم يُعدل منطق الأموال أو الصناديق أو المشتريات أو الـOCR أو الـEdge Functions.

## طريقة التحديث على GitHub Pages

1. احتفظ بنسخة احتياطية من المستودع الحالي (أو أنشئ Commit مستقلًا قبل التبديل).
2. فك ضغط هذا الملف، وانسخ **جميع محتوياته** إلى جذر المستودع الحالي، مع استبدال الملفات ذات الأسماء المطابقة.
3. **لا تحذف أو تستبدل ملفات `config.js` أو `.git` أو `.github` أو ملفات إعداد Git الموجودة لديك**؛ الحزمة لا تحتوي عليها أصلًا. تظل إعدادات Supabase والنشر كما هي.
4. تأكد أن الصفحة الرئيسية `index.html` في **جذر** المستودع، وليس داخل مجلد جديد عند رفع الملفات.
5. نفّذ Commit / Push ثم انتظر اكتمال النشر. افتح الموقع وحدّثه تحديثًا كاملًا (`Ctrl + F5`).
6. **تحقق من كتابة `Web v0.13.2` أسفل القائمة الجانبية** قبل الاختبار. إن بقي v0.13 أو v0.13.1 فأنت ما زلت تشاهد نسخة قديمة أو لم يكتمل النشر.

**لا حاجة لتنفيذ أي Migration SQL من هذه الحزمة** لإصلاح الموظفين والدوام والحفلات، ولا لإعادة نشر `assistant` أو `document-ocr`.
ملفات `database/` و`supabase/` التاريخية موجودة للتوثيق والمحافظة على اكتمال المصدر؛ **لا تعِد تشغيل migrations قديمة** إذا كانت قاعدة البيانات مستخدمة بالفعل.

## اختبارات قبل الاعتماد

توجد خطوات اختبار يدوي في `docs/TEST_EMPLOYEES_ATTENDANCE_EVENTS_V0132_AR.md` واختبارات منطق محلي في `tests/business-rules.test.mjs`، يمكن تشغيلها بواسطة:

```bash
node --test tests/business-rules.test.mjs
```

هذه الاختبارات محلية ولا تختبر حساب Supabase الحي. اختبر الحفظ من الموقع بعد نشره بحساب Owner قبل اعتبار التحديث مؤكدًا.

## التقارير، الصناديق، المشتريات والـOCR

تظل مساراتها الأساسية كما هي. راجع المستندات السابقة في `docs/` للمزيد من التفاصيل، ولا تُعد تنفيذ ملفات قاعدة البيانات القديمة دون مراجعة.
