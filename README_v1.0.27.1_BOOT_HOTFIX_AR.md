# Maria CFO Web v1.0.27.1 — تصحيح خطأ تشغيل الواجهة

## سبب المشكلة

الخطأ الظاهر `does not provide an export named openEmployeeAdjustmentModalV127` يعني أن شاشة الرواتب حُمّلت مع نسخة غير متطابقة من صفحة الموظفين (ملف قديم على الخادم أو في ذاكرة المتصفح). ملف employees.js في الحزمة v1.0.27 الأصلية يتضمن الدالة، لكن المتصفح لم يحصل على النسخة المطابقة.

## الإصلاح

- نقل نموذج تسوية الرواتب إلى ملف مستقل `js/employee-adjustment-modal-v1271.js` تشترك فيه شاشة الرواتب وصفحة الموظف، فلا يعتمد بدء تشغيل الرواتب على وجود تصدير من صفحة الموظفين.
- تحديث مراجع الإصدارات في ملف الدخول ومسارات الاستيراد إلى `1.0.27.1` لمنع اختلاط ملفات JavaScript المخزنة مؤقتًا.
- الاحتفاظ بمنطق التسويات والحسابات وقاعدة البيانات كما كان في v1.0.27 دون تغيير مالي.

## التثبيت

1. لا تعِد تنفيذ SQL ولا تصفّر قاعدة البيانات. إذا كنت قد طبّقت SQL v1.0.27 فلا تحتاج إلى SQL إضافي.
2. ارفع **كل ملفات** الحزمة الجديدة إلى نفس المجلد الذي توجد فيه index.html، ووافق على استبدال الملفات القديمة. **لا تحذف `config.js` الموجود على الاستضافة، ولا ترفع إعدادات قاعدة البيانات الخاصة بك**.
3. تحقق من وجود الملف الجديد على الخادم: `js/employee-adjustment-modal-v1271.js`، ومن أن `js/pages/payroll-v034.js` يشير إليه.
4. افتح الصفحة بعد رفع الملفات بتحديث قوي (Ctrl+Shift+R) أو من نافذة خاصة، وتحقق من ظهور `Web v1.0.27.1`.
5. إذا تكرر نفس الخطأ، تحقق من مسار رفع الحزمة واستجابة الخادم الفعلية، ومن وجود نسخة مخزنة عبر CDN أو service cache. أعد رفع جميع الملفات، لا ملف index.html وحده.

## الاختبارات

اختبارات Node، واختبارات فتح نموذج الرواتب والموظفين على Chromium محليًا مع API محاكية. لم يتم الاتصال بقاعدة Supabase الخاصة بك.
