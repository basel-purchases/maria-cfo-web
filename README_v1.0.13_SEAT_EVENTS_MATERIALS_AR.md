# Maria CFO Web v1.0.13 — المواد والحفلات بالمقاعد

## إصدار المرجع

هذه الحزمة الكاملة مبنية على **v1.0.12**. لا تحتوي على `config.js` أو مفاتيح خاصة، ولا تَعتبر رفع الملفات تنفيذًا لترحيلات قاعدة البيانات تلقائيًا. احتفظ بملف الإعدادات الحالي على الاستضافة.

## 1. صفحة المواد

- أزلنا التمرير الأفقي من **القائمة الأساسية للمواد**. الجدول مختصر (المادة، الوحدة، الرصيد، آخر سعر شراء، سعر USD، السعر المرجعي بالليرة، الإجراء)، وعلى الشاشات الصغيرة يتحول إلى بطاقات رأسية.
- الضغط على المادة أو «التفاصيل» يفتح ديالوغًا يعرض جميع الحقول، ومنها الكود والتصنيف والأسماء الثانوية وتاريخ آخر شراء والجرد المستورد والسعر الوارد في التقرير المستورد. لم نحذف هذه البيانات ولا حقولها من المصدر.
- سعر المادة بالدولار يظهر بثلاث خانات عشرية، ويُقرّب **للأعلى** إلى أقرب 0.001 دولار: `0.4444 → 0.445`. حقل تحرير السعر يبقى رقميًا (لا يحتوي علامة `$`). الأسعار غير المعروفة تبقى بلا قيمة، ولا تُعتبر صفرًا فعليًا.
- ملف SQL يطبّق التقريب للأعلى على **عمليات التسعير والتعديل الجديدة** دون تغيير قسري لكل الأسعار التاريخية بمجرد تثبيته.

## 2. الحفلات والحجوزات دون طاولات

- إنشاء الحفلة يطلب عدد المقاعد المستهدف وليس توزيع طاولات أو حجم طاولة أو رقمها.
- شاشة تخطيط الحفلة تعرض المقاعد المخططة والمحجوزة والمتاحة؛ يحسب النظام الحجز بالأشخاص. مثال: المستهدف 200، حُجز 9، المتاح 191.
- حجز المجموعة يختار صاحب الحجز وعدد الأشخاص وأسماء المرافقين الاختيارية وسعر الفرد وقيمة الحجز وإمكانية القبض الفوري من صندوق. **لا يوجد اختيار طاولة أو قائمة توزيع**.
- إذا أراد المستخدم تحديد مكان جلوس، يمكنه إضافة **ملاحظة نصية اختيارية**؛ لا تمثل حجز طاولة أو حجب مقاعد مستقلة.
- تسجيل الوجبات الخارجية والضيافة والتكاليف والفواتير الإضافية والقبض وتقرير الربح ما زال يعمل عبر عمليات النظام القائمة، لكن **دون توزيع الطلبات على طاولات**.
- يحفظ النظام عدد الحاضرين الفعلي وقت إقفال الحفلة، مستقلًا عن المستهدف والمحجوز.

### التوافق مع قاعدة البيانات القديمة

تحتوي قاعدة البيانات القائمة على جداول وعلاقات تاريخية للطاولات والطلبات الإضافية والضيافة. **لم نحذفها ولم نمسح أي سجل من الماضي**. للمحافظة على دوال الخادم القديمة، ينشئ النظام سجلًا تقنيًا واحدًا داخل `event_tables` للحفلات الجديدة، برمز `__SEAT_SERVICE_V113__`، وهو ليس طاولة للمستخدم ولا يُطلب اختيارها. هذه طبقة توافق داخلية إلى أن تتوفر هجرة أكبر للمحاسبة دون معرّفات جدول.

قد تحتوي حفلات سابقة على قواعد تقديم مرتبطة بتقسيم طاولات قديم. تبقى هذه القواعد التاريخية محفوظة، وتظهر رسالة مراجعة تكلفتها بدل تغييرها بصمت.

## 3. التثبيت بالترتيب

1. **خذ نسخة احتياطية فعلية من قاعدة بيانات Supabase** (ليس مجرد CSV تشخيصي).
2. افحص أن SQL للإصدار **v1.0.12** قد طُبِّق بنجاح، وكذلك الترحيلات السابقة اللازمة للتشغيل.
3. في Supabase → SQL Editor شغّل `database/Maria-CFO-Web-v1.0.13-SEAT-ONLY-EVENTS.sql` كاملًا، وانتظر نتيجة التحقق من الدوال في النهاية. استعلام SQL يفعل تغييرات مخطط وقيم علامة `seat_only_v113`، وليس استعلام عرض فقط.
4. بعد نجاح SQL فقط، ارفع محتويات ZIP كاملة إلى الاستضافة، واستبق `config.js` الموجود على الخادم كما هو.
5. حدّث المتصفح تحديثًا قويًا، وتأكد من ظهور **Web v1.0.13**.
6. جرّب حفلة تطوير جديدة بـ20 مقعدًا، احجز 3 أشخاص دون قبض ثم احجز شخصين بقبض اختباري عبر صندوق اختبار؛ يفترض أن تكون المقاعد المتاحة 15. تأكد من ظهور ملاحظة الجلوس اختيارية ومن عدم وجود اختيار طاولة.
7. تحقق من إدخال/تعديل مادة وسعر دولار `0.4444`، وتأكد أن حقل التحرير يُظهر `0.445` لا نصًا يتضمن رمز عملة.

## 4. حدود الاختبار

اختبارات JavaScript محلية فقط؛ لم تُنفّذ الدوال الجديدة على قاعدة Supabase الحية، ولم يُختبر قبض مالي حقيقي أو إقفال فعلي. تعذّر فحص واجهة Chromium في هذه البيئة؛ تحقق من العرض على الاستضافة قبل استعماله في إنتاج. لا يُنفَّذ حذف أو تصفير للبيانات عند النشر.
