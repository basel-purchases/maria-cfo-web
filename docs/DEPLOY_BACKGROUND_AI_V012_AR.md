# Maria CFO Web v0.12 — المعالجة الخلفية للصور

## الهدف
في v0.12 لا ينتظر المستخدم انتهاء Gemini داخل الصفحة.

المسار الجديد:

1. يختار المستخدم صورة فاتورة أو صور أوردرات.
2. يرسل Maria CFO الصورة إلى `document-ocr`.
3. تنشئ الدالة سجلًا في `ai_jobs` وتعيد `job_id` فورًا.
4. يستمر التحليل في الخلفية عبر `EdgeRuntime.waitUntil(...)`.
5. تُحفظ النتيجة في قاعدة البيانات.
6. يفحص الموقع المهام كل عدة ثوانٍ ويعرض إشعارًا عند اكتمالها.
7. إذا أغلق المستخدم الصفحة وعاد لاحقًا، تبقى النتيجة محفوظة.

## خطوات الترقية

### 1. قاعدة البيانات
شغّل مرة واحدة:

`database/Maria_CFO_Web_v0.12_Migration.sql`

### 2. Edge Function
افتح:

`Supabase > Edge Functions > document-ocr > Code`

واستبدل `index.ts` بمحتوى:

`supabase/functions/document-ocr/index.ts`

ثم Deploy.

لا تحتاج Function جديدة، ولا تحتاج Secret جديد. يستخدم نفس `GEMINI_API_KEY`.

### 3. الموقع
استبدل ملفات الموقع بملفات v0.12 ثم نفذ `Ctrl + F5`.

## فواتير الشراء
زر «تحليل صورة الفاتورة» يرسل الصورة فقط إلى قائمة المعالجة، ثم يمكن للمستخدم مغادرة الصفحة. عند اكتمال التحليل يظهر جرس إشعارات، وعند العودة للفـاتورة يظهر زر «مراجعة النتيجة».

## الأوردرات
في صفحة «الأوردرات والمبيعات» يوجد زر «رفع صور أوردرات» ويدعم عدة صور معًا.

- كل صورة مهمة مستقلة.
- إذا تطابقت كل الأصناف مع قائمة الوجبات والأسعار واضحة، ينشئ Maria CFO مسودة أوردر تلقائيًا.
- إذا كانت هناك مادة غير معروفة أو قراءة غير مؤكدة، لا يخمن النظام؛ تظهر النتيجة ضمن «تحتاج مراجعة».
- لا يتم نشر الأوردر تلقائيًا. النشر المالي يبقى خطوة صريحة من المستخدم.

## نشر الأوردر
إذا لم يكن الصندوق محددًا، يطلب Maria CFO اختيار الصندوق قبل النشر ثم ينفذ `set_order_cashbox` وبعدها `post_order`.
