# فحوص قبول Maria CFO v0.17 (على بيانات تجربة آمنة)

| السيناريو | المتوقع |
|---|---|
| دخول مستخدم غير مصرح | رفض الوصول |
| الصحة `assistant` | يجيب بأن إعداد Supabase موجود أو مفقود بوضوح، ولا يزعم اختبار Gemini |
| «أضف موظفين: أنس يومي 100، زياد شهري 3000» | إضافة الموظفين بنوعي الأجر الصحيحين، دون طلب مسمى اختياري |
| تكرار نفس أسماء الموظفين | رفض التكرار وعدم إنشاء أسماء إضافية |
| «أضف موظف يومي» دون اسم أو أجر | يطلب الحقول اللازمة، ولا ينشئ سجلًا ناقصًا |
| «كم مبيعات اليوم؟» | قراءة RPC الحقيقية، دون أرقام مخترعة |
| «أنشئ أوردر من شاي 2» بلا سعر معرف | طلب السعر بدل اختلاقه |
| صورة مشتريات | يقرأ البنود في جدول قابل للتعديل ويشير إلى انخفاض الثقة؛ لا ينشئ سجلًا بمجرد رفع الصورة |
| اعتماد الصورة | إنشاء **مسودة** بعد موافقة المستخدم؛ لا نشر مالي |
| أمر دفع/نشر | يظهر زر تأكيد وصفي؛ لا صرف قبل ضغطه |
| تكرار تأكيد نفس الاقتراح | لا تنفذ العملية مرتين؛ تظهر رسالة انتهاء/تنفيذ |
| موظف يومي 0/8 ساعات وحالة `full` | لا يظهر له أجر مستحق، مع تنبيه مراجعة |
| موظف يومي حالة `paid_leave` صريحة | يظهر أجر اليوم رغم 0 ساعات وفق سياسة الإجازة المدفوعة |
| موظف شهري 0 ساعات | يبقى الفصل بين النقص المحسوب والتطبيق الإداري وفق القاعدة |
| تعطل Gemini/بلوغ 429 | رسالة واضحة وإمكان بعض الأوامر الصريحة وقراءة البيانات؛ لا إعادة محاولة لعملية كتابة قد نُفذت |
| الروابط في الرد | تفتح الأقسام المعروفة في Maria CFO دون روابط خارجية غير مرغوبة |

**تحذير:** تجارب الصرف والترحيل يجب أن تتم في بيئة اختبار أو بيانات اختبار مع التأكد من صندوق الدفع، لا على معلومات رواتب الموظفين الفعليين. تمثل نتيجة الاختبارات المحلية صحة شفرة البرنامج على الجهاز فقط؛ لا تؤكد عمل اتصال Supabase أو استجابة Gemini على الإنتاج.
