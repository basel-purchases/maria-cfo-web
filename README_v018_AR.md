# Maria CFO — Web v0.18

**حزمة موقع كاملة** تُركَّب فوق الإصدار v0.17 وتضم جميع ملفاته السابقة دون المساس بملف `config.js` أو `.git` أو `.github` أو إعدادات GitHub Pages.

## ما الجديد؟

في **الإعدادات ← الوحدات وعلاقاتها** تستطيع الآن مشاهدة الوحدة وقيمتها والمادة المرتبطة بها، وإضافة وحدة جديدة بقيمة واضحة، وتعديل اسمها وقيمتها، وحذفها إذا لم تكن مستخدمة. أمثلة: «ملعقة سكر = 5 غرام سكر»، «ملعقة سمنة = 10 غرام سمنة». الاسم فريد عالميًا، والوحدة المخصصة لا يمكن ربطها بمادة ثانية. الوحدات العامة، مثل G وKG، تبقى محفوظة ومشتركة.

القيم موجودة في الجداول السابقة: `units` و`material_units` و`unit_conversions`. أضفنا علمًا فقط للوحدة المخصصة (`units.is_material_specific`) ودوال RPC محمية وتحققات، وليس جدولًا ماليًا جديدًا. التحويلات القديمة متعددة الاستخدام تُعرض للمراجعة دون إعادة كتابتها.

## التحديث بالترتيب

1. **نسخة احتياطية:** قاعدة Supabase ومستودع GitHub/آخر Commit.
2. في **Supabase → SQL Editor** نفّذ **فقط** `database/Maria_CFO_Web_v0.18_Migration.sql` مرة واحدة. إذا فشل توقف وأرسل رسالة الخطأ؛ الاستعلام داخل transaction ويتراجع إذا فشل.
3. فك ضغط الحزمة في جذر مشروع GitHub الحالي واستبدل الملفات المتطابقة فقط. **لا تحذف ملفات GitHub الحالية أولًا.** أبقِ `config.js` وملفات Git الموجودة عندك دون تغيير.
4. انتظر نشر GitHub Pages ثم حدّث الموقع بـ `Ctrl+F5` وتأكد من ظهور **Web v0.18** في القائمة الجانبية.
5. افتح **الإعدادات → الوحدات وعلاقاتها** ونفّذ الاختبارات البسيطة في `docs/TEST_UNITS_V018_AR.md`.

**لا حاجة لإعادة نشر Supabase Edge Functions** ولا إعادة تشغيل تحديثات SQL القديمة.

## حدود السلامة

- الوحدات القياسية العامة محمية، والمخصصة الجديدة فريدة ومربوطة بمادة واحدة فقط.
- لا يمكن تغيير نسبة وحدة مستخدمة بمادة أخرى باسمها القديم؛ أنشئ وحدة منفصلة باسم جديد.
- حذف وحدة مرتبطة بوصفة أو مستند أو مادة موجودة يُرفض من قاعدة البيانات. **لا تتجاوز الرفض بحذف يدوي في SQL.**
- تعديل النسبة يؤثر في المعاملات المستقبلية والمسودات؛ التاريخ المالي المنشور لا يُعاد كتابته.
- إذا كان هناك تاريخ قديم يستخدم الاسم العام نفسه لكميات مختلفة، سيُعرض للمراجعة دون تصحيحات تلقائية؛ يحتاج قرار ترحيل منفصل.
