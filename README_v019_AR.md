# Maria CFO Web v0.19 — وحدات العرض، ضبط الصناديق، ومركز الصور المحلي

## الملفات التي تحتاجها

- `database/Maria_CFO_Web_v0.19_Migration.sql`: إصلاح نوع حركات إضافة/سحب الرصيد في الصناديق. **يُشغّل بعد أن تكون ترحيلات v0.18 السابقة مطبقة بالفعل.**
- بقية الحزمة: موقع GitHub Pages كامل وجاهز للاستبدال فوق الموقع الحالي، **باستثناء** `config.js` وملفات Git/إعدادات المستودع الخاصة بك.
- `docs/TEST_IMAGES_V019_AR.md`: خطوات الاختبار الموصى بها بعد النشر.

## ما الجديد؟

### عرض الوحدات الصغيرة دون فقدان الدقة

تظل قاعدة البيانات تحفظ الكمية بوحدة مخزون المادة الأساسية. فإذا كان مخزون السكر يقاس بالكيلوغرام وكانت قيمة ملعقة السكر `0.004 KG`، تظهر في الواجهة بصورة أسهل: **1 ملعقة سكر = 4 غرام**. ويمكنك في محرر العلاقة التبديل بين **غرام** و**كيلوغرام**؛ القيمة المرسلة للحفظ تحوَّل إلى قاعدة المادة، ولا تُعدَّل كميات المخزون التاريخية. ويعمل المبدأ نفسه بين اللتر والملليلتر.

**التبديل المعروض ليس تغييرًا لوحدة المخزون الأساسية نفسها.** لا يمكن تحويل مادة عشوائية بين غرام وقطعة، أو بين وحدتين لا علاقة معروفة بينهما. المعاملات التاريخية لا تعاد كتابتها.

### إصلاح ضبط رصيد الصندوق

الإصدار السابق كان يرسل `transaction_type = adjustment` على نحو يتعارض مع قيد `cashbox_transactions_transaction_type_check`. يعيد ترحيل v0.19 بناء الدالة المحمية `record_cashbox_adjustment_v013` لتستخدم `adjustment_in` للإضافة و`adjustment_out` للسحب، مع الاحتفاظ بنفس واجهة الاستدعاء ودوال السجل النقدي المحمية. لا يحذف القيد ولا يكتب التطبيق مباشرة في Ledger.

### مركز الصور — عمل محلي داخل المتصفح

- صفحة «الصور» الجديدة في القائمة. تدعم ملفات JPEG/PNG/WEBP (حتى 12MB للصورة)، وصورة واحدة أو مجموعة.
- الصور ونتائج التعرف والملاحظات تُخزّن في **IndexedDB داخل المتصفح على هذا الجهاز**. لا تُرفع الصور إلى Supabase بمجرد إضافتها.
- وضعا **استخراج عادي** و**استخراج دقيق** على مستوى الصورة الواحدة أو الصور المحددة/كل الصور. يعمل Tesseract.js في المتصفح بالعربية والإنجليزية؛ يحتاج تحميل ملفات المحرك واللغات من الإنترنت عند أول استخدام.
- لكل صورة: معايَنة على اليمين، بيانات ونص قابلان للتعديل على اليسار، اختيار نوع **أوردر** (الافتراضي) أو **فاتورة شراء**، ومطابقة المواد/الوجبات مع العناصر الموجودة في قاعدة البيانات.
- **حفظ محلي**، **إضافة للبرنامج كمسودة**، و**نشر** بعد تأكيد صريح. المنشور يبقى ظاهرًا مع حالته. النشر الجماعي يختار فقط المستندات المكتملة؛ الصور غير المعالجة والناقصة تبقى داخل المتصفح.
- إذا انقطع الاتصال أثناء إنشاء مسودة أو نشر، تظهر حالة «مراجعة نتيجة العملية» لتجنب تكرار المستند أو المعاملة قبل التحقق مما سُجّل في الخادم.

**تنبيه مهم بخصوص دقة OCR:** المستندات المطبوعة عادة أسهل. «استخراج دقيق» يعني تحسين الصورة وإعادة القراءة، **ولا يعني وجود نموذج متخصص في الخط العربي اليدوي**. لا نعتمد الأسماء أو الأسعار أو الأرقام المستخرجة اعتمادًا نهائيًا دون مراجعة المستخدم؛ قد يحتاج الخط اليدوي إدخالًا يدويًا.

## طريقة التحديث

1. احتفظ بنسخة احتياطية من قاعدة Supabase ومن مستودع GitHub.
2. في Supabase SQL Editor نفذ **فقط** ملف `database/Maria_CFO_Web_v0.19_Migration.sql`. إذا ظهر خطأ، لا تعدّل القيد يدويًا؛ أرسل النص الكامل للخطأ.
3. فك ZIP إلى جذر مستودع GitHub الحالي، واسمح باستبدال الملفات المطابقة. **لا تحذف الموجود أولًا**، ولا تمس `config.js` أو `.git` أو `.github` أو إعدادات GitHub Pages الخاصة بك؛ هذه غير مرفقة في ZIP.
4. نفّذ Commit وانتظر النشر، وحدّث الصفحة بـ `Ctrl+F5`. تأكد من ظهور **Web v0.19**.
5. جرب تعديل علاقة «ملعقة سكر» بالغرام ثم العودة إلى الكيلوغرام، وسجل حركة صندوق اختبار مناسبة، ثم اختبر الصور وفق الدليل المرفق.

## ما لا يتطلب تحديثًا في هذا الإصدار

لا تحتاج لإعادة نشر Supabase Edge Functions (`assistant` أو `document-ocr`) من أجل مركز الصور المحلي. دوال الذكاء الاصطناعي السابقة تبقى كما هي، ولن يؤدي تغيير ملفات GitHub إلى تعديلها.

## قيود مهمة

- الصور المحلية خاصة بالمتصفح والجهاز ولا تتم مزامنتها. حذف بيانات الموقع أو استخدام نافذة خاصة قد يفقد الصور. لا تعتمد على هذا كنسخة أرشفة دائمة.
- في البداية تُحمّل مكتبة OCR وملفات اللغة من خوادم خارجية؛ بعد تحميلها قد تستفيد من ذاكرة التخزين المؤقت، لكن التشغيل الكامل دون إنترنت غير مضمون في هذا الإصدار.
- استخراج النص لا يحوّل الوحدات ولا يقرر الكلفة أو الرصيد. الإنشاء والنشر يعتمدان على RPCs وقواعد الخادم.
- يجب اختبار المسودة والنشر والرصيد في بيئة Supabase الحية أو على بيانات اختبار، ولا تكفي الاختبارات المحلية لضمان نجاحها.

للتدقيق محليًا من جذر المشروع:

```bash
node --test tests/*.test.mjs
```
