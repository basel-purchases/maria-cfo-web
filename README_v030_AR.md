# Maria CFO Web v0.30 FINAL — الإدخالات السريعة المركزية

إصدار كامل مبني على ملف الموقع الحي `Maria-CFO-Web-Live.zip`، دون `config.js` الخاص بصاحب المشروع. لا يحتاج نقل بيانات من إصدار v0.29 يدويًا ولا يتطلب تصفير البيانات.

## ترتيب التنصيب الإلزامي

1. احتفظ بنسخة احتياطية من بيانات Supabase قبل أي ترقية.
2. افتح Supabase > SQL Editor، ثم شغّل كامل الملف:
   `database/Maria-CFO-Web-v0.30-Central-Quick-Imports.sql`
   مرة واحدة. هذا الملف يُنشئ جداول سجل العمليات ووصفات المراجعة والدوال؛ لا يصفر البيانات.
3. انسخ ملفات موقع v0.30 كاملة مكان ملفات الموقع القديمة **باستثناء config.js**: الحزمة لا تتضمنه، فاحتفظ بالنسخة الموجودة على الخادم.
4. حدّث صفحة المتصفح تحديثًا قويًا. سيتغير مؤشر الإصدار إلى `Web v0.30`.
5. افتح «الإدخالات السريعة» قبل «الإعدادات»، واختر من القائمة نوع الملف. اضغط «معاينة الملف» أولًا، ثم «تأكيد الاستيراد».

## الملفات الأربعة

| الترتيب | الاسم المقترح | المحتوى وطريقة الاستيراد |
|---|---|---|
| 01 | `01_المواد_والمنيو_والوصفات.xlsx` | شيت «المواد» وشيت «المنيو والوصفات»؛ كمية الجرد وآخر سعر مادة، أسماء وجبات وأسعار البيع، وصفات مكتملة فقط. |
| 02 | `02_الاساسيات.xlsx` | جرد الأمين؛ يدخل منه قسم الأساسيات فقط، دون المواد أو المنيو. |
| 03 | `03_حسابات_الموردين.xlsx` | كشف حساب الأمين؛ مرجع تاريخي للموردين دون إنشاء حركات صندوق أو دفعات. |
| 04 | `04_حركة_الطلبات.xlsx` أو `حركة الطلبات.xlsx` | حركة طلبات الأمين؛ ينشئ مسودات يمكن مراجعتها، ولا ينشر أوردرات أو مبالغ نقدية. |

**الأسماء غير إلزامية تقنيًا**: نوع الإدخال يُختار من القائمة، وتُحدّد البنية الفعلية من رؤوس شيتات Excel. لا ترفع ملفين مختلفين تحت النوع الخطأ.

## سياسة عدم اكتمال وصفات المنيو

- تنشأ الوجبة باسمها وسعر بيعها حتى لو لم توجد وصفة مكتملة؛ لا ينشئ النظام Food Cost ظاهريًا.
- المادة بلا سعر شراء موجب تمنع رفع ملف المواد، بدل تخزين سعر كاذب.
- الوصفات التي حالتها ليست «منتهي» أو فيها مكوّن/كمية غير معتمدين تُحفظ كمسودات مراجعة في `quick_import_recipe_drafts_v030`، ولا تُنشأ لها بنود تكلفة.
- لا تُحذف قائمة الوجبات بسبب نقص الوصفات. الوصفات المعتمدة تُحفظ في `menu_item_recipe_items`.
- آخر سعر شراء من الشيت الأول مرجع تكلفة؛ ليس فاتورة شراء ولا دفعة مالية جديدة.

## سجل الإدخالات والتراجع

- أسفل الإدخالات السريعة سجل يُظهر وقت ونوع واسم كل ملف وأرقام الإنشاء/التحديث/المراجعة والاستبعاد.
- لكل عملية ناجحة زر «تراجع» صالح مدة **24 ساعة محسوبة على ساعة قاعدة البيانات**.
- يلزم التراجع عن العمليات الأحدث أولًا. يُرفض التراجع آليًا إذا تغيّرت الصفوف بعد الاستيراد أو استُخدم المخزون أو نُشر أوردر، حتى لا تتلف حركات مخزون أو مبيعات أو حسابات.
- كل رفع ملف يتم في معاملة SQL واحدة؛ عند أي خطأ يفشل الرفع بالكامل دون نصف بيانات.
- بصمة SHA-256 تمنع استيراد الملف نفسه مرتين تحت النوع نفسه؛ يمكن رفعه مجددًا بعد التراجع.

## ملاحظات التوافق

- يعتمد استيراد Excel على ملف XLSX سليم، وعلى مكتبة JSZip المضمنة في الموقع.
- اختبار JavaScript المحلي: 165 اختبارًا ناجحًا و7 متروكة لعدم توافر بيانات تاريخية خارج حزمة الموقع أو لاستخدامات قديمة؛ لا أخطاء اختبار وقت التسليم.
- تم اختبار تحليل ملفات المعاينة الحقيقية محليًا، **لكن لم يُنفّذ ترحيل SQL أو التراجع داخل Supabase المتصلة فعليًا**. افحص ذلك قبل اعتماد بيانات مالية حيّة.
- لم تعد واجهة «استيراد الوصفات» القديمة مسارًا مستقلًا؛ الرابط القديم يعيد التوجيه إلى «الإدخالات السريعة».
- لا تستخدم ملف إعادة التصفير من الإصدارات القديمة لأجل هذه الترقية.

## فحص سريع بعد التشغيل

1. فتح الصفحة: ظهور v0.30 والقائمة «الإدخالات السريعة» قبل الإعدادات.
2. اختيار الملف الأول ومعاينة عدد المواد والوجبات والوصفات الناقصة، ثم التأكيد.
3. التحقق من وجبة بلا وصفة: يظهر سعر البيع لكن «التكلفة غير محسوبة».
4. الاستيراد بالترتيب 02 ثم 03 ثم 04 مع مراجعة النتيجة لكل دفعة.
5. تجربة زر «تراجع» على ملف اختبار صغير **قبل استخدام بياناته**، والتأكد من ظهوره بالسجل وأنه يختفي بعد التراجع.
