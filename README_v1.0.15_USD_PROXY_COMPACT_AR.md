# Maria CFO Web v1.0.15 — إصلاح جلب دولار السوق وتبسيط الشريط

## السبب الذي تم إصلاحه

- في Network ظهر طلب LiraScope بحالة HTTP 200، لكن ردّه لم يعلن ترويسة CORS التي تتيح لموقع المشروع قراءة الاستجابة (`Access-Control-Allow-Origin`). نجاح HTTP لا يساوي نجاح JavaScript في قراءة المحتوى.
- في v1.0.14 حاول المتصفح المسار الاحتياطي `market-usd` بعد فشل الطلب المباشر. وجود ملف الوظيفة ضمن ZIP لا ينشرها تلقائيًا على Supabase؛ إذا لم تكن منشورة فالطلب يفشل.
- في v1.0.15 لم يعد الموقع يتصل بـLiraScope مباشرة. يتصل **حصريًا** بوظيفة Supabase `market-usd`، وهي التي تقرأ LiraScope من الخادم ثم تعيد بيانات `marketRates.USD` فقط إلى المتصفح.

## ما يظهر في البرنامج

- في الشريط العلوي، بجوار الإشعارات، **رقم فقط** داخل مستطيل، وسهم `⇄` بداخله للانتقال بين سعر الشراء وسعر المبيع، ثم زر `✓` للاعتماد.
- عند المرور بالمؤشر على السعر يظهر تعريف «سعر الدولار اليوم»، السعر المختار، شراء/مبيع، المصدر ووقت تحديثه. إذا فشل الجلب يظهر سبب الفشل في تلميح المؤشر، دون فقرات داخل الشريط.
- في **الإعدادات > عام > سعر الصرف** أضيف «عرض دولار السوق في الشريط»: الليرة القديمة (14,000) أو الجديدة (140). يُحفظ خيار **العرض فقط** على هذا المتصفح؛ الأسعار الموثقة في قاعدة البيانات تبقى بالليرة القديمة ولا تتأثر بالتبديل.
- زر `✓` يقرأ سعرًا حديثًا من الخدمة أولًا، ثم يفتح خيار «حفظ وتحديث أسعار المواد» أو «حفظ السعر فقط». يعتمد السعر الذي تعرضه حالة الشراء/المبيع المختارة، مع تحويل الليرة الجديدة إلى القديمة ×100 عند الحفظ. لا تحديث تلقائي لأي سعر.
- لا سعر رسمي احتياطي ولا اعتماد لسعر قديم. عند غياب الاتصال يظهر `—` في الخانة، ويشرح التلميح السبب عند تمرير الفأرة. قد يظهر رقم محفوظ مؤقتًا إذا انقطع الاتصال، لكن تلميحه يوضّح أنه محفوظ، ولا يُعتمد دون إعادة التحقق عبر الخدمة.

## التثبيت — مهم: هناك خطوتان منفصلتان

**1) انشر وظيفة `market-usd` أولًا في Supabase، ولا تكتفِ برفع ZIP.**

- افتح **Supabase > مشروعك > Edge Functions**.
- إذا لم تكن الوظيفة موجودة، اختر **Deploy a new function > Via Editor** واسمها حرفيًا `market-usd`. إذا كانت موجودة، افتحها واستبدل كودها بالإصدار الجديد.
- انسخ **كل** محتوى الملف `supabase/functions/market-usd/index.ts` إلى محرر الوظيفة وانشره باستخدام **Deploy function**.
- في إعدادات الوظيفة نفسها، اجعل **Verify JWT = OFF** إذا كان مشروعك يستخدم مفاتيح Supabase الجديدة؛ هذا ضروري لتجاوز بوابة التحقق القديمة التي لا تفهم بعض المفاتيح الجديدة. **الكود لا يسمح بالوصول المجهول**: يتحقق بنفسه من توكن المستخدم عبر `auth.getUser()` ثم من `is_app_owner()`. إذا استخدمت CLI، الملف `supabase/config.toml` يتضمن هذا الضبط.
- لا تضف أسرارًا إلى الموقع؛ الوظيفة تستخدم متغيرات Supabase المُدارة. لا حاجة إلى مفتاح LiraScope لقراءة API العام.

بديل CLI عند الحاجة:

```bash
supabase functions deploy market-usd --project-ref YOUR_PROJECT_REF --no-verify-jwt
```

**2) ارفع ZIP كامل الموقع بعد نشر الوظيفة.** احتفظ بـ `config.js` الموجود في استضافتك؛ لا يوجد داخل الحزمة، ولا ينبغي إرساله. امسح كاش المتصفح أو نفّذ تحديثًا قويًا وتحقق من ظهور `Web v1.0.15`.

**لا يوجد SQL جديد** في v1.0.15، ويُفترض تطبيق ترحيلات التسعير السابقة.

## اختبار التشغيل الصحيح

1. بعد الدخول للبرنامج، افتح Network وفلتر باسم `market-usd`. ينبغي أن ترى **طلب Supabase واحدًا** يؤدي إلى `200` ويعيد JSON فيه `marketRates` وصفّ `USD` وحقولا `buy` و`sell`. لا ينبغي أن ترى طلبًا مباشرًا من المتصفح إلى `lirascope.syria-cloud.sy`.
2. إذا ظهر `404`: الوظيفة غير منشورة بالاسم المطلوب أو على المشروع الذي يتصل به `config.js`. إذا ظهر `401/403`: تحقق من جلسة الدخول وإعداد Verify JWT وصلاحية المستخدم. إذا ظهر `502`: الوظيفة موجودة لكن المصدر غير متاح أو بياناته غير صالحة؛ راجع Logs الخاصة بالوظيفة. لا تغيّر إعدادات الصرف بسبب فشل الجلب.
3. انقر السهم ⇄ وتحقق من تبديل المبلغ بين شراء ومبيع. في الإعدادات اختر العرض بالليرة الجديدة ثم القديمة؛ تتغير الأرقام المرئية فقط.
4. انقر ✓، ثم «حفظ السعر فقط» أولًا، وتأكد من قيمة الصرف في الإعدادات. اختبر إعادة تسعير المواد لاحقًا بعد نسخة احتياطية.

## الضمانات وحدود الفحص

- يمنع الكود استخدام `cbsRates` أو `effectiveRates` أو أي سعر تحويل عالمي بدل السوق الموازية.
- تُرفض الأسعار غير المنطقية وقراءات الوقت المفقودة أو القديمة؛ الليرة الجديدة تُضرب ×100 للحفظ في النظام القديم.
- لا تتغير فواتير الشراء، المخزون أو الصناديق لمجرد عرض سعر جديد.
- اختبارات JavaScript المحلية فقط؛ لم تُنشر الوظيفة على Supabase الخاصة بك، ولم أختبر LiraScope عبر خادمك بالفعل. فحص Chromium البصري لم يكتمل في بيئة التشغيل.
