# Maria CFO Web v0.31 — استيراد الموظفين من Excel (الخيار الخامس)

هذا **تحديث كامل لكل ملفات الموقع** فوق v0.30، باستثناء `config.js` الذي تُبقيه كما هو على الاستضافة. لا يشمل أرشيف المشروع ملف الموظفين الحقيقي الذي زوّدتنا به، حفاظًا على خصوصية الأسماء والهواتف والرواتب. ملفك الأصلي هو الذي سترفعه من داخل البرنامج.

## طريقة التحديث

1. خذ نسخة احتياطية من بيانات Supabase ومن ملفات موقعك قبل التحديث.
2. في **Supabase → SQL Editor** شغّل ملف `database/Maria-CFO-Web-v0.31-Employee-Quick-Import.sql` **مرة واحدة**. يشترط أن ترحيل v0.30 المركزي موجود أصلًا. الملف لا يمسح بيانات أو رواتب أو حركات سابقة.
3. ارفع واستبدل **جميع الملفات** الموجودة في أرشيف `web-v0.31.zip` مكان ملفات الموقع الحالية. **لا تحذف `config.js` الموجود على الاستضافة، لأنه غير موجود في الأرشيف أصلًا.**
4. حدث المتصفح تحديثًا قويًا؛ ستظهر نسخة `Web v0.31`.
5. من **الإدخالات السريعة → 05 · إضافة الموظفين (رواتب شهرية)** اختر ملفك `جدول الموظفين.xlsx`، واضغط **معاينة الملف** ثم **تأكيد الاستيراد**.
6. افتح **الموظفون والرواتب → الموظفون** لتجد الأسماء والوظائف والسكن والموبايلات والرواتب الشهرية.

## أعمدة Excel والتعامل مع البيانات

| Excel | الوجهة | ملاحظات |
|---|---|---|
| الاسم | employees.name | إلزامي؛ يُطابق بالاسم المنظف لتجنّب التكرار |
| الصفة / المهنة | employees.job_title | اختلاف المهنة لا يغيّر الأجر الشهري |
| السكن | employees.residence_v031 | اختياري؛ إذا كان فارغًا لا يمسح البيانات القديمة |
| رقم الموبايل | employees.mobile_phone_v031 | نص؛ بدون افتراض رمز منطقة، ويحافظ على صفر البداية إذا كان نصًا في Excel |
| الراتب | employees.monthly_salary_original | إلزامي وموجب؛ العملة SYP ونوع الأجر monthly |

- يتم تجاهل الصفوف الفارغة وصف الإجمالي بلا اسم، ولا ينشأ موظف وهمي باسم «الإجمالي».
- إن وجد موظف **بنفس الاسم** ويتقاضى حاليًا راتبًا **شهريًا بالليرة السورية**، تُحدّث بياناته وراتبه من الملف دون إنشاء سجل ثانٍ.
- إن وجد بالاسم نفسه لكن نوع أجره يومي/ساعي/مقطوع أو بعملة مختلفة، تُرفض الدفعة كاملة لتجنب تغيير شروطه دون موافقة واضحة.
- ترفض الأسماء المكررة في الملف والرواتب المفقودة أو غير الموجبة، ولا تقبل دفعة ناقصة وسطها أخطاء؛ كل العملية معاملة واحدة.
- لا يُنشئ استيراد الموظفين أي مسير رواتب أو مدفوعات أو قيد صندوق، وإنما يضيف الموظفين كأساس لقسم الرواتب.
- يظل التراجع من سجل الإدخالات خلال **24 ساعة** مشروطًا بعدم تعديل سجلات الموظفين أو استخدامها في الدوام/الرواتب/السلف بعد الاستيراد، وبعد التراجع عن أي استيرادات أحدث أولًا.

## المعاينة والتحذيرات

- يعرض البرنامج عدد الموظفين وبياناتهم كاملة **داخل متصفح صاحب المشروع** قبل الحفظ، مع تنبيه لأي راتب مرتفع نسبيًا دون تغييره تلقائيًا.
- يظل ملف Excel الأصلي ببياناته الشخصية منفصلًا عن ملفات كود الموقع، **ولا يُضمّن داخل حزمة النشر**.

## الاستيرادات الأربعة السابقة

الخيارات 01 (المواد والمنيو والوصفات)، 02 (الأساسيات)، 03 (الموردين)، 04 (الأوردرات) مستمرة بنفس دوال v0.30 دون تغيير. يتشارك الخيار الخامس معها سجل العمليات وحماية منع تكرار بصمة الملف والتراجع المحمي.

## الاختبار

استُخدم `node --test tests/*.test.mjs` للتحقق من اختبارات JavaScript المحلية. يتضمن الإصدار اختبارات جديدة لتنسيقات الأسماء والرواتب وأرقام الموبايل، وقراءة الجدول الفعلي. **لم نُنفّذ SQL ضد قاعدة Supabase الحية في هذه البيئة**؛ جرّب الترحيل والاستيراد أولًا على نسخة اختبار من قاعدة بياناتك إن أمكن.
