# Maria CFO Web v1.0.4 — أسماء بديلة للوجبات واستيراد الأوردرات حسب التاريخ

## ما الجديد؟

- في «الوجبات والوصفات» → «تعديل الوجبة والتقدير»: حقل «أسماء أخرى للوجبة»، اسم بديل في كل سطر. تُخزَّن كأسماء مرتبطة **بنفس الوجبة ونفس الوصفة**، وليست أصنافًا جديدة. تُعرض في البطاقة، ويبحث حقل المنيو عنها وفي اسم الوجبة الرئيسي، ويضمها تصدير Excel/PDF.
- في «الأوردرات» → معاينة Excel: يعرض النظام تطابق الاسم الرئيسي أو البديل. وإذا كان اسم الملف غير معروف، يجب الاختيار صراحةً: **«اسم آخر لوجبة موجودة»** ثم البحث في القائمة واختيار الوجبة، أو **«إنشاء صنف جديد مستقل»**. لا ينشئ صنفًا جديدًا بصمت.
- يطابق `1 كغ كباب حلبي` مع `كباب حلبي` عندما يكون التطابق الوحيد بعد حذف كمية/وحدة **من بداية الاسم فقط**، كما يدعم `1كغ` و`١ كغ` وبعض أسماء الكيلو/الغرام/اللتر. المطابقة الدقيقة لها الأولوية؛ المطابقة الملتبسة لا تُختار عشوائيًا.
- عند المطابقة التلقائية بعد حذف كمية/وحدة، تحفظ المبيعات كما هي، لكن **لا تُنسب تكلفة وصفة الحصة العادية إلى كيلو/لتر مباع** دون تحويل موثّق؛ يُعرض هذا السطر ناقص التكلفة للمراجعة، حتى لا تُحتسب أرباح مضللة.
- في «إدخال الأوردرات»: اختيار تاريخ واحد اختياري لتقرير يوم قديم. إذا تركته فارغًا فتواريخ Excel تبقى كما هي؛ تغيير التاريخ لا يغيّر التاريخ/الساعة المصدرية المخزنة للمراجعة. عند وجود أكثر من يوم في Excel لا نسمح بدمجها كلها في تاريخ واحد بالخطأ.
- في الوصفات: غلق نافذة المكونات دون تغيير لا يعيد رسم المنيو، ولا يفقد البحث/صفحة النتائج/مكان العمل. عند إضافة/تعديل/حذف مكوّن محفوظ يتم تحديث بيانات المنيو اللازمة مع بقاء الفلاتر.

## ترتيب التثبيت (مهم)

1. **احتفظ بنسخة احتياطية قابلة للاستعادة من Supabase وأحدث نسخة الموقع/الفرع.** لا تستخدم CSV التشخيصي كبديل عنها.
2. في Supabase → SQL Editor نفّذ الملف الكامل:
   `database/Maria-CFO-Web-v1.0.4-Menu-Aliases-Daily-Orders.sql`
   بصلاحية مدير قاعدة البيانات، **بعد** تحديثات SQL السابقة حتى v0.41. انتظر نجاح جميع الاستعلامات و`COMMIT`. إذا فشل أي أمر لا تنشر الموقع قبل معالجة الخطأ.
3. **بعد نجاح SQL** فك ZIP الكامل واستبدل ملفات الموقع في جذر مستودعك (عدا `config.js` الموجود لديك، فهو غير موجود داخل ZIP). حافظ على `.git` و`.github` وإعدادات GitHub Pages.
4. ارفع الملفات إلى فرع النشر، ثم حدث الصفحة بقوة (`Ctrl+Shift+R`)، وتحقق من عبارة **Web v1.0.4** أسفل القائمة.
5. اختبر تغيير اسم بديل من إحدى الوجبات ثم البحث عنه؛ جرّب **معاينة** تقرير Excel ذي يوم واحد بتاريخ سابق قبل تأكيده. لا تعتمد ملفًا تجريبيًا على القاعدة الحية إلا إذا كنت تقصد حفظه.

## ما الذي تغير في القاعدة؟

- جدول جديد `public.menu_item_aliases_v104` يحفظ أسماء بديلة ذات مفتاح مطابقة فريد، مرتبط بجدول `menu_items`. لا يمكن أن يشير الاسم البديل إلى أكثر من وجبة، ولا أن يتعارض مع الاسم الرئيسي لوجبة أخرى.
- View للبحث/الصفحات `public.menu_item_search_v104`.
- RPC لحفظ الوجبة وأسمائها وتقدير تكلفتها **ضمن معاملة واحدة** (`menu_save_v104`) ودوال مطابقة/إضافة أسماء بديلة محمية بصلاحية المالك.
- تعديل آمن لتوقيعي `ameen_price_preview_v041` و`ameen_import_daily_v041` **دون تغيير أسماء الاستدعاء أو إعادة تحميل البيانات**؛ المعاينة والحفظ يستخدمان نفس محلّل أسماء المنيو. تبقى حماية بصمة الملف والتكرار ورقم الأوردر وتاريخه.
- عمود تشخيصي جديد `ameen_daily_lines_v041.match_kind_v104`، مع تحديث تقرير الأوردرات كي لا يحتسب تكلفة حصة عادية لبيع مُعرّف بوزن/وحدة مختلفين تلقائيًا.
- **لا يحذف هذا التحديث أي بيانات تشغيل قديمة، ولا يحوّل تقارير الكاشير إلى قبض صندوق أو خصم مخزون جديد.**

## أمثلة المراجعة

1. موجود بالمنيو «مرتديلا حلبية»، وظهر في Excel «مرتديلا»: في عمود القرار اختر «اسم آخر لوجبة موجودة» ثم ابحث عن «مرتديلا حلبية» وحددها. عند تأكيد استيراد **جديد** سيسجَّل «مرتديلا» كاسم بديل لتلك الوجبة.
2. موجود «كباب حلبي»، وظهر «1 كغ كباب حلبي»: يُطابق تلقائيًا إن كان هو التطابق الوحيد، ويُحافظ على سعر الملف. السعر الرئيسي للمنيو **لن يتغير تلقائيًا** لمجرد اختلاف سعر كيلو، وتكلفة الحصة تبقى بحاجة مراجعة تحويل.
3. إذا ظهر اسم غير معروف فعلًا: اختر «إنشاء صنف جديد مستقل»، مع الانتباه أن تكلفته ووصفته تحتاجان لاحقًا لاستكمال.
4. إذا لم تعدّل وصفة ثم ضغطت × أو خارج النافذة فلن يعاد تحميل القائمة أو تفقد موضع التصفح.

## حدود التطوير والتحقق

- تشغيل SQL ونشاطه الفعلي لم يُختبرا على Supabase الخاصة بك؛ لا يمكن إثبات نجاح الخادم دون تنفيذ ملف الترحيل هناك.
- الأسماء الملتبسة بسبب وجود صنفين بنفس الاسم قد تتطلب تنظيف أسماء المنيو أولًا بدل إنشاء أو اختيار صنف عشوائي.
- الأسماء البديلة الجديدة تُستخدم في الاستيرادات القادمة. التقارير المستوردة سابقًا لا يعاد تعديل بنودها أو أسعارها آليًا، ولا يعاد استيراد نفس بصمة الملف باسم جديد.
- كويري التصفير DEV القديم الذي يتوقف عند ظهور جداول غير معروفة **سيتوقف** بعد إضافة `menu_item_aliases_v104`. لا تُشغّل كويري التصفير القديم في بيئة تشغيل؛ إذا لزم تصفير تجارب مستقبلًا جهّز نسخة مُراجعة تتعامل مع هذا الجدول وتحفظ البيانات الحقيقية المطلوبة.
